# AI 티(AI Slop) 제거 기준 — 웹 디자인·카피·이미지

> 출처 1: 코딩애플 「AI 냄새가 싫다는 사람들」(2026-08, 조회 27만) 스크린샷 분석
> 출처 2: Forblune 자체 관찰(24개 예시 사이트 1차 생성물) + 업계 통념
> 용도: 예시 사이트 빌더/리뷰어가 **반드시** 적용하는 금지·대체 규칙. 위반은 "AI 티"로 판정한다.

---

## 0. 왜 문제인가 (영상 요지)

- 상품 설명·뉴스·코드 리뷰·웹사이트에서 **AI 출력을 그대로 복사한 듯한 콘텐츠**가 양산되면서 사용자가 피로감을 느끼고, "AI 냄새"가 나면 신뢰가 떨어진다.
- 웹 디자인에서 AI 슬롭 느낌을 주는 주범: **획일화된 폰트, 누런(크림색) 디자인, 의미 없는 UI 요소, 이모지 남발, 클릭되지 않는 버튼처럼 생긴 요소, shadcn류 기본 컴포넌트 그대로 쓴 무난함**.
- 해법의 핵심: **자동 생성에 맡기지 말고 직접 개입**(색 조합 직접 선택, 레퍼런스 확보), **원샷이 아니라 반복 수정**, **AI 이미지는 조명·질감·구도를 구체적으로 지정하고 타이포는 따로**, **AI 문체 대신 자기 말투**, 그리고 **명령을 내리는 사람의 도메인 지식이 병목**이다.

## 1. 영상 스크린샷에서 지적된 구체적 신호

| # | 신호 | 화면 근거 | 판정 |
|---|---|---|---|
| 1 | **누런 배경 + 똑같은 폰트** (spanlens.io) — 크림/웜 옐로 배경, Inter/Geist류 산세리프 + 모노스페이스 소제목 "WHAT YOU GET" | "누런 디자인에 똑같은 폰트… 전부 다 클로드의 기본" | 크림 배경 자체가 아니라 **이유 없이 기본값을 그대로 쓴 것**이 문제 |
| 2 | **헤드라인 위 깜빡이는 점 알약(pill) 배지** "• 문제" (agentsroom.dev) | "왼쪽에 점이 깜빡이는 것도 AI 느낌" | 아이브로우 pill + 펄스 dot = 1순위 금지 |
| 3 | **아이콘 3장 카드 그리드** — 둥근 사각 틴트 배경 안 아이콘 + 굵은 제목 + 2줄 설명 ×3 | agentsroom "터미널 탭 지옥 / 도대체 누가 끝낸 거죠? / 머리가 과부하" | 구조 자체가 템플릿. 특히 다크 배경 + 글로우 카드 |
| 4 | **이모지 대충 쓰기** — 🤖 ✨ 🧠 ⚡ 🔍 를 브랜드 아이콘 대신 사용 (engineprompt.net) | "이모지 대충 쓰는 것도 AI스럽고요" | 이모지 = 아이콘 금지 |
| 5 | **버튼처럼 생겼는데 클릭이 안 되는 요소** — 알약 칩(ChatGPT/Gemini/Claude…)이 버튼처럼 보이지만 동작 없음 | "버튼처럼 생겼는데 클릭했을 때…" | 어포던스 거짓말 금지 |
| 6 | **shadcn류 기본 컴포넌트 그대로** — 검은 pill 버튼, 회색 outline, 12~16px radius 카드, 1px 보더 | "Shadcn 같은 UI 프레임워크 쓰라고 하면 평범하고 무난" | 무난 = 개성 없음. 프레임워크 자체가 아니라 **커스터마이즈 없음**이 문제 |
| 7 | **세리프 제목 + 산세리프 본문 + 모노 태그의 "고급스러운 척" 조합** (engineprompt "Ready to supercharge your AI workflow?") | 화면 | 세리프 헤드라인 + "supercharge" 류 카피 = 전형 |
| 8 | **AI 문체** — 고급스럽지만 영혼 없는 문장 | 요약 4번 | 카피 규칙(§5) 적용 |
| 9 | **AI 이미지의 이질감** | 요약 3번 | 실사 지시·조명·질감·구도 명시, 텍스트는 이미지에 넣지 않음 |

## 2. 레이아웃·구조에서의 AI 티 (금지 → 대체)

| 금지 패턴 | 왜 AI 티인가 | 대체 |
|---|---|---|
| **중앙 정렬 히어로 공식**: 아이브로우 pill → 초대형 제목(그라데이션 텍스트) → 2줄 부제 → 버튼 2개(검정 primary + "자세히 보기 →") → 로고 월 | 수천 개 랜딩이 동일 | 스타일별 히어로 문법을 따른다(Editorial: 이미지가 주인공·좌측 정렬 / Kinetic: 풀블리드 대형 타이포 / Cinematic: 장면+한 문장 / Corporate: 사실+수치+CTA / Product: 제품 UI가 주인공). 카테고리 문서 §12 참고 |
| **3열 아이콘 카드**(아이콘 틴트 박스 + 제목 + 설명) | 정보가 아니라 "기능이 있다"는 형식만 전달 | 실제 UI 조각·사진·수치·구체 문장으로 대체. 카드가 필요하면 열 수·크기·비율을 비대칭으로, 아이콘 대신 번호·실제 이미지 |
| **통계 3~4개 행** "10K+ 사용자 / 99.9% / 24/7" | 근거 없는 숫자 | 사실적·검증 가능한 수치 1~3개, 단위와 기준일 명시. 없으면 넣지 않음 |
| **"고객 후기" 이니셜 원형 아바타 3장** | 가짜 인물 | 이름·회사·역할을 구체화하거나, 후기 대신 실제 결과 서술. 아바타 원형 이니셜 금지 |
| **FAQ 아코디언 → 그라데이션 최종 CTA 밴드 → 4열 푸터** 순서 | 템플릿 흐름 | 순서와 형태를 스타일에 맞게 재구성. 최종 CTA는 배경 밴드 대신 문장형/조용한 형태도 가능 |
| **모든 카드 동일 radius(12~16px)+1px 보더+미세 그림자+hover translateY(-2px)** | 클로드/shadcn 기본값 | 프로젝트별 radius 규칙(0 / 2 / 4 / 24 등)을 **의도적으로** 결정, 카드 경계는 여백·선·배경차 중 하나만 |
| **섹션마다 동일한 "라벨(모노 대문자) → H2 → 설명" 반복** | 리듬 없음 | 섹션마다 형태를 바꾼다(풀블리드 이미지, 2열 텍스트, 목록, 표, 인용) |
| **글래스모피즘 카드, 메시 그라데이션 블롭 배경, 보라→파랑 그라데이션** | 2023~24 AI 랜딩 전형 | 단색·사진·질감·타이포로 깊이를 만든다 |
| **다크 배경 + 네온 글로우 카드 + 그리드 라인 배경** | "AI 스타트업" 전형 | 다크가 필요하면 질감·명암·타이포 위계로 |

## 3. 색·타이포에서의 AI 티

- **누런 크림 배경(#FAF9F6, #FDFBF7류)을 이유 없이 사용** → 카테고리 팔레트에서 **의도적으로** 고른 색을 쓴다. Editorial의 아이보리는 "화보 종이 질감"이라는 이유가 있어야 하고, 텍스트·포인트 색이 함께 설계돼야 한다.
- **Inter / Geist / Space Grotesk / Playfair Display 조합을 기본값처럼 사용** → 한국어 사이트는 Pretendard·Noto Sans KR·나눔명조·Gowun Batang·IBM Plex Sans KR·SUIT 등에서 **브랜드 성격에 맞춰 선택**하고, 영문 디스플레이 서체를 쓰더라도 이유를 적는다. 한 사이트 안에서 서체는 최대 2개(디스플레이+본문), 모노스페이스는 코드·표 숫자에만.
- **모노스페이스 대문자 아이브로우 라벨**("WHAT YOU GET", "01 / FEATURES") 남발 → 섹션 라벨은 필요할 때만, 스타일에 맞는 형태(Cinematic은 자간 넓은 대문자 허용, Editorial은 작은 이탤릭/숫자, Corporate는 일반 소제목).
- **그라데이션 텍스트, letter-spacing -0.02em 굵은 헤드라인 일괄 적용** → 헤드라인 크기·굵기·행간은 스타일 DNA대로(Editorial Light~Medium, Kinetic Black, Cinematic 압축형 Bold, Corporate Semi-bold).
- **역할 없는 색**(포인트 3~4색이 장식으로만) → 색마다 역할(CTA, 상태, 카테고리) 부여. Kinetic도 "역할 없는 색 제거"가 원칙.

## 4. 컴포넌트·인터랙션에서의 AI 티

- **pill 배지 + 펄스 dot** (`● NEW`, `● 문제`, `● Live`) — 전면 금지. 상태 표시가 필요하면 텍스트/작은 정사각 마커/밑줄.
- **이모지를 아이콘·불릿·헤더 장식으로 사용** — 전면 금지. 아이콘은 인라인 SVG(단일 굵기, 프로젝트 공통 스트로크), 또는 숫자·문자.
- **버튼처럼 보이는데 동작 없는 요소**(pill 칩, 카드 hover) — 링크/버튼이면 실제 동작(href·JS), 아니면 버튼 스타일(배경·보더·pill) 제거. hover 효과는 클릭 가능한 것에만.
- **✨ 스파클·🚀 로켓·"AI-powered" 배지** — 금지.
- **화살표 "→"를 모든 링크·버튼에 붙이기** — 한 페이지에서 화살표는 1~2곳(주요 CTA)만.
- **체크 아이콘 리스트(✓ ✓ ✓)로 기능 나열** — 문장·표·실제 화면으로.
- **가짜 브라우저 창 목업(신호등 3개 점)** — Product 스타일에서 UI 목업을 쓸 때 브라우저 크롬 대신 실제 앱 화면 구성 그대로.
- **스크롤 시 모든 요소 fade-up 일괄** — 모션은 스타일 리듬대로, 대부분 요소는 즉시 표시. Utility/Corporate는 등장 애니메이션 없음.
- **hover translateY(-2~4px) + shadow 확대 일괄** — 카드가 링크일 때만, 스타일에 맞는 반응(Editorial: 이미지 컷 전환 / Kinetic: 배경 색 전환 / Cinematic: 밑줄·화살표).

## 5. 카피에서의 AI 티 (한국어)

금지 어휘·구문:
- 과장·공허: "혁신적인", "차세대", "압도적인", "완벽한", "손쉽게", "한 차원 높은", "새로운 경험", "특별한 순간", "최고의", "궁극의", "당신만을 위한", "지금 바로 시작하세요", "~를 경험하세요", "~의 모든 것", "스마트한", "프리미엄", "역대급", "무조건", "한정 특가"
- 영어 직역체: "~를 위한 최고의 선택", "~와 함께하세요", "당신의 ~를 한 단계 업그레이드", "seamless/effortless/elevate/unlock/supercharge/empower"의 번역
- 구조적 티: **모든 것을 3개씩 나열**(제목 3단, 기능 3개, 이유 3개), "~뿐만 아니라 ~까지", "A. B. 그리고 C." 리듬, 문단 끝마다 요약문, 섹션 제목이 전부 명사구 4자
- 형식적 티: 제목에 마침표 없이 문장 끊기 "빠르게. 정확하게. 안전하게.", 느낌표, "!" 남발, 큰따옴표로 감싼 슬로건

대체 원칙:
- 카테고리 카피 공식(Scene→Mood→Selection / Verb→Capability→Action / Belief→Process→Proof / 사실→근거→행동)을 따르되 **구체 명사와 숫자**를 넣는다: "빠른 배송" → "오후 2시 전 주문, 다음날 새벽 도착"
- 사람이 실제로 쓰는 문장 길이·리듬(짧은 문장과 긴 문장 섞기), 브랜드마다 다른 말투(존댓말/해요체/문어체) 결정
- 한 페이지 안에서 같은 단어("경험", "가치", "솔루션") 3회 이상 반복 금지
- 사실이 없으면 문장을 지운다. 채우기 위한 문장 금지

## 6. 이미지에서의 AI 티

- **내용과 무관한 랜덤 스톡 사진**(스니커 드롭 히어로에 대나무숲, 건축 스튜디오에 해파리) — 1차 생성물의 가장 큰 결함. → 키워드 기반 이미지 `https://loremflickr.com/<w>/<h>/<keyword1>,<keyword2>?lock=<n>` 로 교체하고 alt에 실제 내용 서술. 키워드는 영어 명사 1~2개(예: `sneakers,streetwear`, `architecture,concrete`, `perfume,bottle`, `omakase,chef`, `yoga,studio`, `vegetables,market`). `lock` 값으로 고정.
- 스타일 필터는 유지(Cinematic grayscale, Editorial saturate 낮춤)하되 **주제가 맞는 사진**이 우선.
- 이미지가 필요 없는 스타일(Product/Utility)은 사진 대신 실제 UI/데이터를 그린다.
- 로드 실패 대비 배경색·비율 고정(aspect-ratio)로 레이아웃 시프트 방지.

## 7. 코드·구조에서의 AI 티

- 모든 섹션 `<section class="section">` + `container` + `section-label / section-title / section-desc` 3종 세트 반복 → 섹션별 의미 있는 클래스·구조
- CSS 변수 이름 `--primary/--secondary/--accent` 로만 구성 → 역할 기반 이름(`--ink`, `--paper`, `--cta`, `--rule`)
- 주석에 "// Hero Section", "// Features" 영어 대문자 → 상관없지만 콘텐츠 흔적이 남지 않게
- `lorem`, `placeholder`, `TODO`, `여기에` 잔존 금지

## 8. 리뷰어용 판정 체크리스트 (파일당 실행)

각 항목을 grep/육안으로 확인하고 결과를 기록한다. **1개라도 해당하면 수정.**

1. `pill|badge|eyebrow` 요소에 dot/pulse 애니메이션이 있는가
2. 이모지 문자가 마크업에 있는가 (아이콘·불릿·제목) — `[\u{1F300}-\u{1FAFF}☀-➿]`
3. 3열 아이콘 카드 그리드가 있는가(아이콘 박스 + h3 + p 반복 3~4개)
4. 히어로가 중앙 정렬 + pill + 그라데이션 텍스트 + 2버튼 구조인가
5. "10K+ / 99.9% / 24/7" 류 근거 없는 통계 행이 있는가
6. 이니셜 원형 아바타 후기 카드가 있는가
7. 모든 카드가 동일 radius+1px 보더+shadow+hover 상승인가
8. Inter/Geist/Space Grotesk/Playfair 를 이유 없이 로드하는가
9. 모노스페이스 대문자 아이브로우 라벨이 3개 이상인가
10. 클릭 불가한데 버튼/칩처럼 보이는 요소가 있는가
11. 화살표 "→"가 4곳 이상인가
12. 금지 카피 어휘(§5)가 있는가 / 3개씩 나열이 3섹션 이상 반복되는가
13. 이미지 주제가 콘텐츠와 무관한가(picsum 랜덤) → loremflickr 키워드로 교체
14. 그라데이션 블롭·메시·글로우·글래스 카드가 있는가
15. 스크롤 fade-up이 전 요소에 일괄 적용됐는가

## 9. 빌더용 사전 규칙 (요약)
