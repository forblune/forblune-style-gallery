## 0. 표준 명명 규칙과 4항목

모든 프로젝트는 `Primary Style / Product Type / Tone` 순서로 표기한다.
- f0ring → `Editorial / Commerce / Soft · Curated`
- FlyOne V1 → `Kinetic / Brand Landing / Bold · Energetic`
- FlyOne V2 → `Cinematic / Portfolio / Serious · Human`

고정 4항목:
1. **Primary Style** — 사이트가 어떤 감정과 인상을 만드는가
2. **Product Type** — 랜딩, 포트폴리오, 커머스, SaaS 등 실제 목적
3. **Tone** — Soft, Bold, Serious, Technical 등 표현의 온도와 태도
4. **Core Message** — 방문자가 한 문장으로 무엇을 느껴야 하는가

5축 시스템: Primary Style · Product Type · Core Emotion(Desire/Excitement/Trust/Clarity…) · Persuasion Mechanism(이미지/움직임/사람과 철학/근거와 구조) · Interaction Rhythm(Slow/Balanced/Fast)

**핵심 원칙**: 대표 스타일은 하나만. CTA 구조는 Product Type이 결정하고, 시각 표현은 Primary Style이 결정한다. 색상보다 **정보 위계, 이미지 선택, 문장 리듬**이 스타일을 더 강하게 결정한다. 70(Primary)·20(Secondary)·10(Accent) 혼합 원칙.

피해야 할 혼합: 네온+세리프 에디토리얼+기업형 아이콘+시네마틱 흑백을 한 화면에 / 빠른 모션과 긴 철학 문장을 같은 위계에서 경쟁 / 카드마다 다른 모서리·그림자·타이포 체계 / 색상만 바꾸고 콘텐츠 구조는 그대로.

## 2. Editorial (기준 사례: f0ring — Editorial Commerce)

**한 문장**: 상품을 판매하기 전에 브랜드의 취향을 먼저 보여주는 사이트.
**핵심 느낌**: 감각적 · 여성적 · 에디토리얼 · 라이프스타일 · 큐레이션 · 여백 · 취향 · 부드러움
**설득 순서**: 분위기 → 상품 이미지 → 선택 → 구매. 고객이 아니라 같은 취향의 독자로 대한다.

디자인 문법
- 화보처럼 큰 이미지, 얇고 세련된 타이포(제목 Light~Medium), 짧은 문장과 넓은 여백
- 정돈된 상품 그리드 + 비정형 에디토리얼 블록 혼합, 좌측 정렬 기본, 비대칭으로 매거진 리듬
- 색: 순백 대신 아이보리·오프화이트 배경, 검정 대신 짙은 차콜 텍스트, 포인트는 베이지·연핑크·브라운 저채도. 밝기 차이로 구분(강한 컬러 충돌 금지). 구매 행동에서만 대비를 높임
- 히어로: 주인공은 이미지. 로고·한 문장·CTA만. CTA는 "컬렉션 보기", "새로운 셀렉션" 같은 제안형
- 상품 카드: 테두리 대신 여백으로 구분, 배지는 작고 절제, 호버 시 다른 컷으로 전환
- 내비: Shop·New·Editorial·About 정도로 축약, 얇은 헤더, 스크롤 시 축소 고정
- 모션: 느리고 부드러운 페이드, 미세한 이동, 크로스페이드. 바운스·네온·빠른 회전 금지
- 푸터: 중성색, 뉴스레터는 할인보다 새 셀렉션 소식, 로고+짧은 브랜드 문장으로 마무리

카피: 장면 → 감정 → 선택(Scene → Mood → Selection). 제안형, 감각 동사(입다·머물다·스며들다·고르다). "역대급·무조건·한정 특가" 금지. 예: "일상에 자연스럽게 스며드는 옷." / "천천히 고른 것들." / "이번 주의 새로운 셀렉션."
CTA: 새로운 셀렉션 보기 · 컬렉션 보기 · 자세히 보기

기본 페이지 구조: 화보형 Hero → 시즌/무드 소개 → 큐레이션 상품 → 에디토리얼 콘텐츠 → 상품 탐색과 구매 → 브랜드 노트

유지 기준: 이미지보다 UI가 먼저 보이지 않게 / 감성 때문에 가독성 희생 금지 / 구매 정보는 구체적으로 / 저채도만으로 Editorial이 되지 않음(편집 리듬과 이미지 선택이 핵심) / 모바일에서 여백 과잉으로 구매 흐름 길어지지 않게

## 3. Kinetic (기준 사례: FlyOne V1 — Kinetic Brand Showcase)

**한 문장**: 짧은 시간 안에 기술력과 에너지를 강하게 각인시키는 사이트.
**핵심 느낌**: 강렬함 · 속도감 · 에너지 · 기술 · 컬러풀 · 대형 타이포그래피 · 스포츠 · 디지털
**설득 순서**: 임팩트 → 기술력 → 작업물 → 문의. 3초 안에 속도·장르·전문 분야가 드러나야 함.

디자인 문법
- 풀스크린(90~100vh) 히어로, 화면 가득 채우는 대형 영문 산세리프(Extra Bold/Black, 촘촘한 행간, 좁은 자간)
- 색: 블랙·딥 네이비·차콜 배경 + 라임·시안·코랄·퍼플 등 선명한 포인트. 색에 역할 부여(서비스·카테고리·버튼 구분). 글로우는 핵심 CTA/숫자에만 약하게
- 큰 숫자(01·02·03, 프로젝트 수), 12열 그리드+비대칭, 대각선·오프셋으로 진행 방향, 화면 가장자리까지 사용
- 카드: 이미지가 카드 전체, 짧고 굵은 제목, SPORTS·BRAND 같은 짧은 태그, 호버 시 확대·텍스트 이동·컬러 오버레이, 가로·세로 비율 혼합
- 서비스 카드: 번호 크게, 2~3문장, 능력 태그, 호버 시 배경 전체가 활성 색으로
- 내비: Work·Services·Equipment·Contact, 투명→스크롤 시 진해지고 낮아짐, 문의 버튼 우상단 상시
- 모션: 빠름. 슬라이드+짧은 페이드, 마스크 리빌·줄 단위 등장, 카운트업, 마키 텍스트, 추적형 커서 가능. 방향·속도·타이밍 일관. `prefers-reduced-motion` 대응 필수
- 정적인 구간을 반드시 넣어 대비를 만들 것

카피: 동사 → 능력 → 행동(Verb → Capability → Action). 선언형·명령형. Move·Chase·Fly·Break·Capture·Push. "가로지르다·추적하다·더 가까이". 내용 없는 "혁신·미래·최고" 반복 금지. 예: "MOVE BEYOND LIMITS." / "빠른 장면을 더 가까이."
CTA: Showreel 보기 · 프로젝트 문의

기본 구조: 풀스크린 Hero/영상 → 대표 작업 쇼릴 → 핵심 서비스 → 장비·기술 → 프로젝트 그리드 → 빠른 문의 CTA

유지 기준: 역할 없는 색 제거 / 영어 슬로건만으로 전문성 대신 금지 / 강한 인상 뒤 반드시 신뢰·안전·진행 방식 정보 / 흑백으로도 Kinetic 가능(핵심은 움직임·대형 타이포·빠른 리듬)

## 4. Cinematic (기준 사례: FlyOne V2 — Cinematic Narrative Portfolio)

**한 문장**: 작업자의 철학과 과정으로 전문성을 증명하는 사이트.
**핵심 느낌**: 시네마틱 · 진중함 · 전문성 · 장인정신 · 인물 · 철학 · 다큐멘터리 · 저채도 · 신뢰
**설득 순서**: 사람 → 철학 → 과정 → 작업물 → 문의. 관객이 아니라 제작 파트너와 대화하듯.

디자인 문법
- 흑백 또는 저채도 이미지, 포인트 컬러 한 가지만(오렌지·앰버·브론즈 중 택1)을 링크·작은 선·번호·CTA에만
- 배경: 블랙·차콜·웜 블랙, 밝은 섹션은 아이보리·웜 그레이. 대비는 색이 아니라 밝기·질감·공간
- 타이포: 크지만 소리치지 않는 압축형 산세리프, 섹션 라벨은 자간 넓은 대문자, 본문 3~6문장 허용, 행간 넓게, 본문 폭 55~75자 제한, 인용문은 크기·여백으로 분리
- 인물 소개: 작업 중인 자연스러운 모습, 이름 크게·직무 작게, 현재 역할→작업 방식→경험→철학, 판단 기준 한 문장 인용
- 작업 철학: 원칙 3~5개, 신념→과정→증거, 큰 인용문·번호·얇은 구분선
- 대표 작업: 영화 스틸 같은 썸네일, 연도·클라이언트·역할 메타, 2~4문장 설명, 크레딧처럼 역할 표기
- 과정: Brief → Route → Safety → Flight → Review 식의 단계와 체크리스트("꼼꼼하게" 대신 무엇을 확인하는지)
- 내비: Work·Pilot·Process·Equipment·Contact, 투명→짙은 단색, 문의 버튼은 작고 차분
- 모션: 느림. 긴 페이드, 느린 줌·패럴랙스·크로스페이드, 디졸브, 필름 그레인 정도. 시선을 안내하되 끌지 않음
- 문의: "프로젝트를 이야기해 주세요" 협업 어조, 카운트다운·가짜 마감 금지, 회신 기대치 명시
- 푸터: 가장 짙은 색, 철학 한 줄, ©·지역·직무 작게

카피: 신념 → 과정 → 증거(Belief → Process → Proof). 차분한 선언형+구체적 서술형. intention·path·frame·timing·precision / 의도·동선·타이밍·프레임·현장 판단. 근거 없는 "최고의·혁신적인·압도적인" 금지. 예: "빠르게 비행하는 것보다 정확한 장면을 만드는 것이 중요합니다." / "모든 움직임에는 이유가 있습니다."
CTA: 작업 방식 알아보기 · Selected Work 보기 · 프로젝트 이야기하기

기본 구조: 대표 장면/인물 → 작업자 소개 → 철학과 인용문 → Selected Work → 과정과 역할 → 조용한 문의 CTA

유지 기준: 어두운 배경만으로 Cinematic 아님 / 긴 글은 사례와 과정으로 증명 / 자화자찬 아닌 역할·행동 / 느린 모션이 조작 반응까지 느리게 하지 않게 / 흑백만 반복 말고 대표 작업의 색도 적절히 / 마지막에 명확한 문의 경로

## 5. Corporate (Notion 정의: 신뢰와 정보 — 기업·병원·법률·B2B) — 파생 기준

**한 문장**: 근거와 구조로 "이 조직은 믿을 수 있고 무엇을 하는지 바로 이해된다"를 만드는 사이트.
**핵심 감정**: Trust + Clarity. **설득 수단**: 실적·인증·구성원·절차·수치. **리듬**: Balanced.
Editorial의 취향, Kinetic의 임팩트, Cinematic의 인물 서사와 달리 **정보 구조 자체가 설득**이다.

디자인 문법
- 배경: 화이트·라이트 그레이, 짙은 네이비/딥 그린/차콜 등 안정된 브랜드 색 1개 + 중성색. 포인트는 CTA·링크·아이콘에 제한
- 타이포: 가독성 최우선의 산세리프, 제목은 Semi-bold, 본문 16px 이상, 명확한 위계(H1~H3)
- 그리드: 12열 정렬, 카드 규격 통일, 섹션마다 명확한 제목+요약문+근거
- 히어로: 무엇을 하는 조직인지 한 문장 + 핵심 수치/인증 + 명확한 CTA(상담 예약·문의·자료 다운로드)
- 필수 섹션: 서비스/진료과목/업무 분야 → 왜 우리인가(수치·인증·연혁) → 구성원/전문가 → 절차(How it works) → 사례/고객사 → FAQ → 오시는 길/연락처
- 신뢰 요소: 사업자 정보, 위치, 운영시간, 인증 로고, 실명 구성원, 절차 명시. 병원·법률은 과장 광고 금지 톤
- 내비: 5~7개 메뉴 + 우상단 CTA, 스크롤 시 고정 흰 배경, 상단 유틸리티 바(전화·언어) 가능
- 모션: 절제. 짧은 페이드업, 카운트업 정도. 장식적 모션 금지
- 푸터: 정보 풍부(사이트맵·주소·전화·사업자등록번호·정책 링크)

카피: 사실 → 근거 → 행동. 명확·존중·과장 없음. "국내 최초·1위" 같은 근거 없는 표현 금지. CTA: 상담 예약 · 진료 예약 · 문의하기 · 회사소개서 다운로드
잘못 쓰면: 패션 브랜드에 Corporate를 과하게 쓰면 취향보다 기능 설명이 먼저 보인다.

## 6. Product (Notion 정의: 기능과 사용성 — SaaS·앱·플랫폼) — 파생 기준

**한 문장**: 기능이 실제로 어떻게 작동하고 무엇이 좋아지는지를 보여주어 "쓰고 싶다"를 만드는 사이트.
**핵심 감정**: Clarity + 기대. **설득 수단**: 제품 UI 시연, 사용 흐름, 수치화된 이점, 소셜 프루프. **리듬**: Balanced.

디자인 문법
- 배경: 화이트 또는 아주 옅은 틴트, 제품 UI 목업이 시각의 중심. 브랜드 색 1개 + 그라데이션 소량
- 타이포: 현대적 산세리프, 헤드라인은 이점 중심("~를 10분 만에"), Bold, 본문은 짧은 단락
- 히어로: 한 줄 가치 제안 + 서브카피 + 주 CTA(무료 시작) + 보조 CTA(데모 보기) + 제품 스크린샷/UI 목업(CSS로 그린 가짜 앱 화면 OK)
- 필수 섹션: 로고 월(사용 팀) → 핵심 기능 3~4개(각각 UI 조각 + 이점) → 작동 방식(1·2·3) → 통합/호환 → 고객 후기(수치) → 가격표(2~3 플랜) → FAQ → 최종 CTA
- UI 목업은 실제 인터페이스처럼: 카드·테이블·토글·차트를 CSS로 구성. 텍스트 박스로 대체 금지
- 내비: Product·Features·Pricing·Docs·Login + CTA 버튼
- 모션: 기능 시연에 봉사하는 모션(탭 전환, 스크롤 시 UI 하이라이트). 장식 금지
- Editorial만 적용하면 기능과 사용 흐름이 모호해진다는 경계 참고

카피: 문제 → 해결 → 결과. 구체적 수치, 동사 중심. CTA: 무료로 시작하기 · 데모 보기 · 문서 보기

## 7. Commerce (Notion 정의: 탐색과 구매 — 쇼핑몰·예약·판매) — 파생 기준

**한 문장**: 원하는 것을 빠르게 찾고 안심하고 결제하게 만드는 사이트. Commerce는 **사이트 목적**이며 Editorial Commerce, Kinetic Commerce처럼 다른 스타일과 결합 가능하지만, 여기서 Primary가 Commerce인 경우는 **탐색·비교·구매 효율**이 시각을 이긴다.
**핵심 감정**: Desire + Clarity(찾기 쉽다, 믿고 산다). **리듬**: Balanced~Fast.

디자인 문법
- 배경: 화이트, 상품 이미지 중심, 브랜드 색 1개 + 세일/혜택용 액센트 1개(역할 있는 색만)
- 상단: 검색창이 크고 명확, 카테고리 내비, 장바구니·로그인, 배송/혜택 안내 바
- 히어로: 프로모션 배너 또는 시즌 기획전(캐러셀 가능) + 빠른 카테고리 진입
- 필수 섹션: 카테고리 바로가기 → 오늘의 특가/베스트 → 상품 그리드(이미지·이름·가격·할인율·별점·리뷰수·배송 정보) → 기획전/큐레이션 → 리뷰/신뢰(배송·교환·인증) → 최근 본/추천 → 푸터(고객센터·정책·사업자)
- 상품 카드: 명확한 가격 위계, 할인 전후 표시, 품절/재고 표시, 찜·장바구니 즉시 액션
- 예약형(Booking)이면: 날짜/시간/인원 선택 위젯, 실시간 잔여, 가격 요약, 취소 정책 명시
- 필터·정렬 UI 명확, 모바일 2열 그리드, 하단 고정 CTA
- 모션: 즉각 반응, 로딩 스켈레톤, 과한 장식 금지

카피: 혜택 → 상품 → 안심. 명확한 숫자, 정직한 재고·기간 표시(가짜 긴급성 금지). CTA: 장바구니 담기 · 바로 구매 · 예약하기
DNA 지표(파생): 감성 3 · 시각 강도 3 · 모션 2 · 서사 1 · 사람 1 · 정보 밀도 5 · 직접 전환 5 · 전문 신뢰 3

## 8. Experimental (Notion 정의: 독창성과 경험 — 캠페인·아트·브랜드 이벤트) — 파생 기준

**한 문장**: 정보 전달보다 **경험 자체**가 메시지인 사이트. 방문자가 "이런 건 처음 본다"고 느끼게 한다.
**핵심 감정**: Surprise · Curiosity. **설득 수단**: 인터랙션, 비관습적 레이아웃, 타이포 실험, 시간 기반 연출. **리듬**: 가변(의도적).

디자인 문법
- 관습 파괴가 목적이지만 **의도가 읽혀야** 한다: 한 가지 실험 개념(예: 스크롤이 시간이다, 커서가 붓이다, 글자가 물체다)을 정하고 끝까지 밀어붙인다
- 색: 극단 허용(모노크롬 + 형광 1색, 또는 풀컬러 그라데이션), 단 개념에 종속
- 타이포: 초대형·변형·가변폰트·회전·겹침 허용, 그러나 핵심 정보(무엇·언제·어디서·CTA)는 반드시 읽혀야 함
- 레이아웃: 격자 이탈, 겹침, 풀블리드, 가로 스크롤, 스티키 스크롤텔링 등
- 인터랙션: 커서 추적, 마우스 위치 기반 변형, 스크롤 연동 애니메이션, 클릭으로 상태 변화 — 순수 CSS/JS로 구현(외부 라이브러리 금지)
- 반드시 포함: 캠페인/전시의 핵심 정보 블록(제목·기간·장소·참여 방법), 접근성 대안(`prefers-reduced-motion` 시 정적 버전), 키보드로 도달 가능한 CTA
- 로딩/인트로 연출 허용(3초 이내, 스킵 가능)

카피: 질문 → 경험 → 초대. 짧고 시적이되 정보 블록은 사실적으로. CTA: 참여하기 · 예약하기 · 경험 시작

## 9. Utility (Notion 정의: 효율과 업무 — 대시보드·ERP·내부 도구) — 파생 기준

**한 문장**: 반복 업무를 빠르고 실수 없이 끝내게 하는 도구. 감정보다 **통제감과 속도**.
**핵심 감정**: Control · Efficiency. **설득 수단**: 데이터 가시성, 상태 명확성, 즉각 반응. **리듬**: Fast(반응 속도), 시각은 정적.

디자인 문법
- 레이아웃: 좌측 사이드바(내비) + 상단 바(검색·알림·프로필) + 메인 콘텐츠. 데스크톱 우선, 태블릿 대응
- 색: 라이트 또는 다크 테마 1개 기준(둘 다 지원 가능), 중성 그레이 스케일 + 브랜드 색 1개 + 상태 색(성공·경고·오류·정보)은 의미로만 사용
- 타이포: 시스템 산세리프 또는 Inter/Pretendard류, 13~15px 본문, 숫자는 tabular-nums, 위계는 굵기와 크기 소폭 차이
- 컴포넌트: KPI 카드(수치+증감), 차트(CSS/SVG로 그린 막대·선·도넛), 데이터 테이블(정렬·필터·페이지네이션·행 선택·상태 배지), 폼(인라인 검증), 모달/드로어, 토스트, 탭, 빈 상태, 로딩 스켈레톤
- 밀도: 높음. 여백은 최소 기능적 수준, 정보 스캔 속도 최우선
- 인터랙션: 즉각 반응(<100ms 느낌), 호버 행 하이라이트, 키보드 단축키 힌트, 검색 명령 팔레트(⌘K) 등
- 모션: 거의 없음. 상태 전환 150~200ms
- 반드시 실제 업무 시나리오 데이터를 채울 것(빈 텍스트 박스·lorem 금지). 한국어 업무 용어

카피: 명확한 라벨, 동사형 버튼(저장·발주·승인), 상태는 명사(대기·처리중·완료). 마케팅 문구 없음

## 10. 스타일 판단 의사결정 (새 프로젝트)

1. 사용자가 사이트를 보고 가장 먼저 어떤 감정을 느껴야 하는가? → 갖고 싶다(Editorial) / 강렬하다(Kinetic) / 믿을 수 있다(Cinematic) / 이해하기 쉽다(Corporate·Product)
2. 구매·문의·이해·사용 중 최종 행동은?
3. 이미지·결과물·사람·데이터 중 신뢰의 핵심은?
4. 빠르게 훑는가, 천천히 몰입하는가?

잘못 선택 시: 고급 전문 서비스에 Kinetic 과다 → 가볍고 유행 따르는 인상 / 패션에 Corporate 과다 → 기능 설명 우선 / 빠른 전환 캠페인에 Cinematic 과다 → CTA 도달 지연 / Product에 Editorial만 → 기능·흐름 모호

## 11. 흔한 오해
- Editorial ≠ 무조건 미니멀 (핵심: 이미지·큐레이션이 정보보다 먼저 설득)
- Kinetic ≠ 무조건 컬러풀 (핵심: 움직임·대형 타이포·빠른 리듬)
- Cinematic ≠ 무조건 어두움 (핵심: 인물·서사·과정·느린 리듬)
- Commerce는 시각 스타일이 아니라 목적
- 트렌디 ≠ MZ 스타일 (타이포·모션·색·서사·설득 구조로 판단)
