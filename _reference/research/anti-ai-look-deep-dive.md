## 1. 요약

- AI 티는 취향 문제가 아니라 통계 문제다. 모델은 학습 분포의 최빈값을 내고, 그 최빈값이 사이트마다 같기 때문에 사용자가 알아본다 [1][20][25].
- Show HN 랜딩 1,590개 스캔에서 4개 이상 패턴이 겹친 페이지가 22%, 2~3개가 32%였다. 상위 5개는 그라데이션 배경 28%, 손대지 않은 shadcn 23.5%, 중앙 정렬 제목 23.5%, 다크+회색 본문 20.3%, 피처 카드 그리드 20.1% [1][2].
- 위 수치의 강도는 제한적이다. Krebs 감사는 오탐 5~10%를 스스로 인정하고 스크린샷을 쓰지 않아 "크림+세리프" 같은 시각 판단 항목은 측정 대상이 아니었고, claudecodehq의 "상위 텔"은 on-topic 댓글의 2.0~2.5% 언급률이다. 두 수치는 성격이 다르므로(DOM 감사 vs 댓글 언급률) 이 문서는 정량 순위가 아니라 카테고리별 리스크 목록으로 쓴다. 1,590건 감사의 원저자는 Krebs이며 developersdigest는 인용자다 [1][7][149].
- 1세대 텔(보라 그라데이션·중앙 히어로·3카드)은 우리 1차 기준서가 이미 다룬다. 2026년의 2세대 텔은 크림 배경+세리프+테라코타, 이탤릭 세리프 단어, 장식 번호·스크롤 큐·버전 배지처럼 "고급스러운 척"하는 계열이며, 우리 Editorial·Cinematic이 정확히 이 지뢰를 밟기 쉽다 [6][7][8][27].
- 데이터상 텔이 아닌 것도 있다. 벤토 그리드, 다크모드 자체, Tailwind/shadcn 도구 자체는 문제가 아니고 "손대지 않은 기본값"이 문제다 [7][19]. 단, 초판이 "메시/블롭 배경은 데이터상 텔이 아님"으로 완화한 것은 오독이었다. claudecodehq의 "Cleared by Data"는 무죄 판정이 아니라 Reddit 텍스트에서 키워드가 GitHub `/blob/` URL과 섞여 측정 불가였다는 뜻이고, DOM을 실제 검사한 Krebs 감사에서는 그라데이션 배경이 28%로 1위, 컬러 글로우가 별도 항목이다. 메시·블롭·글로우 금지는 그대로 유지한다 [7][1].
- 색·서체 금지 목록은 유통기한이 짧다. 2025-10에 대안으로 권장된 Space Grotesk·Playfair가 1년 만에 새 텔이 됐다 [10][3][111]. 목록이 아니라 선택 절차와 이유 기록이 기준이어야 한다 [26][18].
- 카피의 AI 티는 명사보다 동사·형용사에서 나고(초과 어휘의 66%가 동사) [64], 어휘보다 구조(문장 길이 균일, 접속어, 대조 구문, 무견해)가 더 확실한 신호다 [63][70][88][89].
- 이미지는 "미드저니 룩" 6요소(과채도·유광 피부·균일 조명·과한 보케·대칭·그레인 0)로 판별되며 [93], 소비자 98%가 실사 이미지를 신뢰의 핵심으로 본다 [106]. 장식용 이미지는 사용자가 무시한다 [105].
- 결론 다섯 가지: (1) 리뷰는 단일 항목이 아니라 겹침 개수로 판정한다 [1][63]. (2) 크림·앰버·세리프는 hex 단위로 클로드 팔레트를 피하고 이유를 문서화한다 [28][8]. (3) 서체·색은 목록이 아니라 절차로 고른다 [26]. (4) 원샷 대신 토큰 플랜→자기비판→코드→요소 단위 수정 루프를 강제한다 [6][23]. (5) 손맛은 모션이 아니라 타이포·그리드·구체성에서 나온다 [47][62][74].

## 2. AI 티가 생기는 근본 원인

### 2-1. 모델의 기본값 = 학습 분포의 최빈값
- 모델은 학습 데이터 분포 안에서 가장 확률 높은 패턴으로 수렴한다. 보라·Inter·다크는 "가장 실패하지 않는 조합"이라 선택된다 [20].
- 인디고 CTA의 기원은 구체적이다. Tailwind UI가 5년 전 모든 버튼을 `bg-indigo-500`으로 만들었고, 이 코드가 튜토리얼과 GitHub에 대량 복제돼 모델이 "웹 버튼=인디고"로 학습했다. 제작자 Adam Wathan이 2025-08 공개 사과 트윗을 남겼다 [25][9][10].
- 크림 배경의 기원도 구체적이다. Claude.ai 캔버스가 #faf9f5, 포인트 #cc785c, 제목 세리프+본문 산세리프다. "경쟁사의 쿨 블루·슬레이트와 반대되는 웜톤"이라는 Anthropic 브랜드 전략이며 생성물이 이 UI를 물려받는다 [28]. Anthropic 자체 스킬 문서도 "웜 크림(#F4F1EA 근처)+고대비 세리프+테라코타"를 AI가 몰리는 3대 룩의 1번으로 명시한다 [6].
- 다크+글로우+글래스는 Linear.app 유행의 평균이다. Raycast·Reflect·Supabase가 복제해 2025년에 이미 "단조롭다"는 비판을 받았고, 모델은 그 유행의 평균을 다시 낸다 [29].
- 이미지 모델도 같다. 학습 데이터에 스튜디오 조명 상업 사진 비중이 크고, 크라우드소싱 미적 선호로 추가 최적화되며, 디퓨전의 손실 압축이 고주파(질감)를 먼저 지운다. 결과가 유광·과채도·대칭이다 [94][93].

### 2-2. 프롬프트 부재
- 색·서체 미지정 = 인디고+Inter+둥근 모서리+0.1 opacity 그림자+3열 그리드+그라데이션 텍스트 히어로 [42].
- Anthropic 쿡북: "지시가 없으면 Claude는 흰 배경과 보라 배경의 단순한 디자인으로 기본 회귀한다"고 명시. 같은 프롬프트에 미학 블록을 넣으면 결과가 달라진다 [111].
- 같은 프롬프트를 Claude Code 원본 / Claude 웹 / frontend-design 플러그인 3환경에서 비교하면 원본은 "안전한 선택의 예측 가능한 실행"이고, 차이는 능력이 아니라 지시다 [113].

### 2-3. 프레임워크·도구 기본값
- shadcn/Tailwind 자체는 데이터상 텔이 아니다. 손대지 않은 shadcn이 23.5%로 텔이다 [1][7].
- Lovable/Bolt/v0류는 다크 배경·보라-파랑 그라데이션·pill 버튼·Inter/Geist·모든 카드에 Lucide를 기본 룩으로 낸다 [16].
- 스킬을 써도 새 지문이 생긴다. awesome-claude-design은 틸 #16d5e6, 깜빡이는 상태 점, 카드 좌측 바, 히어로 3열 그리드, Lucide 기본, 이미지 생성기가 토큰을 무시하는 것 등 8개를 목록화했다 [114].

### 2-4. 원샷 생성과 컴포넌트별 평균 회귀
- 각 컴포넌트가 학습 평균으로 따로 회귀한다. "버튼의 평균과 카드의 평균은 서로 조율된 적이 없다." 그래서 균일함(모든 카드 동일)과 부조화(radius 혼용, 광원 두 개인 그림자, 7/13/19px 간격)가 동시에 나타난다 [14].
- 지시 없이 생성하면 "아이브로우+64pt 헤드라인+서브+CTA 2개 중앙 히어로, 3-up 카드, 로고 수프, 프라이싱 토글, FAQ 아코디언"으로 수렴한다. Anthropic이 스킬로 개선을 시도한 뒤에도 그렇다 [23][24].
- Anthropic 스킬은 그래서 코드 전에 2패스를 강제한다: 토큰 시스템을 먼저 적고, "어떤 비슷한 페이지에도 낼 법한 기본값"을 지목·수정한 뒤에 코드를 쓴다 [6].

### 2-5. 템플릿 반복의 정당한 원인(반례)
- 히어로→사회적 증거→기능→CTA 순서는 20년 A/B 테스트로 굳은 전환 공식이며, 사용자가 이미 학습했다. 순서를 뒤집으면 마찰이 생긴다 [43][45].
- 노코드 빌더의 사전 최적화 레이아웃, Stripe/Linear 모방, MVP 출시 압박이 SaaS 사이트를 똑같게 만든다. 처방은 구조 폐기가 아니라 "구조는 유지, 스토리텔링 교체" [44].
- HN에서는 이 패턴이 "2010년대 테크 스타트업 사이트, Bootstrap 시대"의 유산이라는 지적이 있고, Krebs도 "슬롭 페이지도 전환은 잘 된다"고 단서를 단다 [19][1].
- 그래서 우리 규칙은 "순서"가 아니라 "형태와 채우는 방식"을 바꾸는 쪽이다.

## 3. 신호 카탈로그

판정 원칙: 단일 신호로 판정하지 않는다. 위키백과 AI Cleanup 팀도 "문제의 잠재적 신호이지 문제 자체가 아니다"라고 명시한다 [63]. Krebs 데이터의 상위 5개 중 2개 이상, 또는 아래 표의 A급 1개+B급 2개가 겹치면 수정 대상 [1].

### 3-8. 보강 신호와 판정 정리(비평 각도)

초판의 4개 각도(tells-ui·typography-color·layout-components·copywriting)를 빠진 관점·근거 강도·상호 모순·우리 상황 적합성으로 재검토한 결과다. 위 표에 끼워 넣은 항목(브로드시트, 사업자정보 푸터, 한글 폴백, Tailwind CDN, 접근성, 한국어 구조 신호, 번역 목록 경고, 이미지 물성 신호) 외에 판정 원칙 자체를 손본 것은 아래 셋이다.

- **균일 vs 부조화는 모순이 아니라 축이 뒤바뀐 것이다.** 초판은 "균일함(동일 카드 길이·py-24·같은 radius)"과 "부조화(radius 혼용·광원 2개·off-grid 간격)"를 둘 다 텔로 적어 상충처럼 읽혔다. 정리하면 시스템 축(radius·그림자·간격 사다리·아이콘 굵기)은 1값으로 고정돼야 하고, 콘텐츠 축(카드 텍스트 길이·열 폭·섹션 패딩·이미지 크기)은 내용에 따라 달라야 한다. AI 출력은 정반대로 시스템 축이 흔들리고 콘텐츠 축이 균일하다 [14][5]. 체크리스트는 두 줄로 나눈다: (1) 시스템 축 — radius 스케일 1개, 그림자 1광원, 간격 4/8/12/16/24/32/48/64만, 아이콘 1패밀리 1굵기 (2) 콘텐츠 축 — 한 섹션 카드 텍스트 1~4줄 혼재, 섹션 패딩 2~3단계 차등, 이미지 span 2종 이상.
- **국내 유통 "토스급 UI" 공식의 보라 고정은 채택하지 않는다.** 널리 읽히는 한국어 바이브코딩 가이드는 "강조색은 앱 전체에서 딱 하나, 보라 하나, 나머지 회색", "그림자 opacity 4%", "검정은 #2A2A2A"를 프로 UI 공식으로 제시한다. 강조색 1개·그림자 절제 원리는 맞지만 색을 보라로 고정한 것은 Tailwind indigo-500에서 비롯된 AI 퍼플+shadcn 룩을 그대로 재생산한다. 국내 빌더/에이전트가 이런 글을 참조하면 우리 기준과 충돌하므로, "보라 하나+회색" 공식이 들어온 결과물은 §3-2 위반으로 처리한다 [158][25].
- **뷰포트는 데스크톱·모바일 둘 다 검사한다.** "한국은 모바일 퍼스트"라는 가정과 달리 Statcounter 2026-07 한국 페이지뷰는 데스크톱 61.15% / 모바일 37.92% / 태블릿 0.92%로 데스크톱 우세다(트래커 표본 특성 주의). 스마트폰 보유율은 98.8%다. AI 단일 HTML은 보통 데스크톱 1뷰포트만 정돈되고 모바일에서 히어로 타이포가 깨지거나 nav가 동작 없는 햄버거로 남는다. 리뷰는 1440·1024·390px 3뷰포트 스크린샷을 필수로 하고, 데스크톱의 "텅 빈 큰 화면"(py-24 과여백)과 모바일의 "히어로 4줄 초과·overflow-x·동작 없는 햄버거"를 각각 검사한다. 한쪽만 통과하면 실패 [159][160].
- 근거가 약한 출처(aitoolpick.org·superfiles.in·hypedge.com·qwe.edu.pl 스니펫·이미지 텔 도구 블로그)는 "관찰 일치"로만 취급하고 단독 근거로 규칙을 만들지 않는다. taste-skill 76,753 stars(2026-08-16 GitHub API)와 Anthropic 스킬의 3클러스터 문구는 원문 확인됨 [149][6]. 미해결: 한국 웹접근성(KWCAG 2.2) 규정 대조, Product/Utility의 빈 상태·에러 상태 없는 "해피패스만 있는 목업" 텔은 근거를 확보하지 못해 제외했다.

## 4. 사람 손맛을 만드는 원칙

### 4-1. 레퍼런스: 하나가 아니라 이질적인 둘
- 스타일 DNA는 단일 레퍼런스가 아니라 이질적 레퍼런스 2개의 리믹스("Linear의 타이포 규율 + Pitchfork의 편집 색")로 정의해 통계적 중심에서 벗어난다 [23].
- 안티 레퍼런스(닮으면 안 되는 사이트)를 브리프 필수 항목으로 둔다. Impeccable /init이 청중·보이스·안티 레퍼런스를 먼저 묻는 이유다 [115].
- 국내 실무도 같다. 원샷 대신 스크린샷 참조·회사 헤더/푸터 복제·실제 제품 이미지 투입이 "AI 티 제거"의 방법이었다 [22]. 기업의 기존 디자인 자산을 추출해 모든 생성물에 일관 적용하는 것이 "AI 결과물이 흔히 노출하는 이질감"의 완화책이라는 국내 매거진 정리도 같은 방향이다 [129]. 예시 사이트 생성 전 브랜드 자산(워드마크, 실제 색, 사진 톤, 말투 샘플)을 먼저 확정해 입력하고, 자산 없이 생성한 페이지는 "초안"으로 표기한다.
- "세련되게/모던하게/프리미엄으로 만들어줘" 같은 형용사 지시는 결과를 서로 닮게 만든다. 국내 실무자의 처방은 글래스모피즘·브루탈리즘·벤토 그리드·Y2K처럼 스타일 고유 명칭을 정확히 지정하는 것이다 [126]. 빌더 프롬프트에서 형용사 지시는 금지하고 카테고리 DNA 문서의 스타일 고유명(Swiss grid, Brutalist, Editorial magazine)과 레퍼런스 URL로 지시한다.
- 레퍼런스가 없으면 모델은 "토큰과 컴포넌트에 충실한 안전하고 단조로운 디자인"에 안주한다. 같은 위시리스트 UI를 Mobbin MCP / Lazyweb MCP / Playwright 방문 / 웹검색 4가지 수집법으로 만든 비교에서, 레퍼런스가 있을 때만 구조가 뚜렷이 달라졌다(SHEIN 카드형, Airbnb 다중 보드형). 디자이너는 빈 화면에서 시작하지 않고 예시를 보고 발산한 뒤 수렴한다 [141]. 카테고리별 실제 사이트 스크린샷 3~5장을 로컬 레퍼런스 보드로 저장해 브리프에 첨부하고, 토큰만 주고 생성하는 것은 금지한다.

### 4-2. 아트디렉션: 주제에서 도출된 은유 하나
- Awwwards SOTY 2025(Lando Norris)의 손맛은 템플릿 밖 형태가 아니라 주제(F1 속도)에서 나온 은유였다: 날카로운 전환, 시네마틱 스크롤, 인물 성격을 반영한 대화체 섹션 [61].
- 심사위원은 "섹션 전체를 관통하는 단 하나의 강한 아이디어"를 보상하고, 효과를 쌓는 것은 "통제력 부족"으로 읽는다 [48].
- Anthropic 스킬: "대담함은 한 곳에만 쓴다(Spend your boldness in one place)". 페이지가 기억될 시그니처 요소 하나를 토큰 플랜에 먼저 적는다 [6].
- Awwwards 공식 가중치는 Design 40 / Usability 30 / Creativity 20 / Content 10. 손맛을 모션으로 만들려 하지 않는다 [47].

### 4-3. 의도적 선택: 기본값에서 어긋난 지점을 적는다
- 디자이너의 역량은 "AI가 제안한 기본값을 그대로 받아들여도 되는가"를 묻고 어디서부터 어긋날지 정하는 것 [20].
- 서체 선언 옆에 이유 1줄. 이유를 못 적으면 그 서체는 기본값이다 [18].
- 각 예시 사이트 스펙에 "기본값에서 의도적으로 어긋난 지점 3개"(색·서체·레이아웃 각 1개)를 명시하고 리뷰어가 확인한다 [20].
- 보이스는 고정하고 톤만 상황에 따라 바꾼다. 보이스는 "X but not Y" 쌍 3개로 정의하고("담백하지만 무뚝뚝하지 않게"), 에러·결제 실패 같은 톤 예외를 함께 적는다. 명확함이 재미보다 먼저다 [76].
- 값을 전부 못박는 프롬프트는 "기술적으로 맞지만 시각적으로 죽은" 결과를 낸다. 사람은 시스템(서체 후보·팔레트 역할·히어로 문법)을 정하고, AI는 그것을 일관되게 적용하는 실행 계층으로 쓴다 [112]. 토스 디자이너의 정리도 같다. AI는 "괜찮은 시스템이 정의되어 있다면 꽤 준수한 결과물"을 내지만 "바로 사용할 만한 화면"은 아니며, 디자이너의 일은 AI가 더 나은 결과를 내도록 원칙과 시스템을 설계하는 쪽으로 옮겨간다 [137]. 그래서 빌더 산출물은 규칙 문서의 품질로 평가한다. 결과물을 손으로 고치기보다 규칙 문서를 고쳐 재생성하는 것을 우선하고, 규칙 없이 손으로 고친 예외는 기록한다.
- 국내 서체 업계가 본 2026 방향은 "사람의 흔적"이다. 투박하고 손맛이 느껴지는 표현, 완벽하지 않아서 더 진짜 같은 형태, 글자가 형태·질감·공간의 주인공이 되는 타입 중심 디자인이 AI의 완벽함과 대비되는 신뢰 요소로 꼽혔다 [130]. Editorial/Kinetic에는 타이포가 주인공인 섹션을 최소 1개 두고, 손맛 장치는 §4-6대로 1종만 쓴다.

### 4-4. 리듬: 그리드와 문장 모두
- 에디토리얼 그리드는 폭이 다른 트랙(full / content / breakout / split)을 이름 붙여 정의하고 섹션마다 폭을 바꾼다 [49].
- 표준 열 사이에 좁은 열(skinny column)을 끼운 비대칭 모듈 그리드가 정돈된 레이아웃에 에너지를 준다. 캡션·번호·날짜를 좁은 열에 [50].
- 매거진 레이아웃은 "아무것도 깔끔한 행·열에 맞지 않는" 불균등 스팬과 1곳의 겹침으로 만든다. 페이지당 1~2곳 [51].
- 스위스 스타일의 정의는 모듈 그리드+비대칭+flush-left ragged-right다. 중앙 정렬 대칭 히어로는 스위스가 아니다 [52].
- 비대칭 히어로는 컬럼 비율을 명시(7:5, 8:4)하고 DOM 순서=읽기 순서를 지킨다. 모바일에서 단일 컬럼으로 접히는지, overflow-x가 없는지 확인한다 [53].
- 문장도 같다. 5단어 문장만 반복하면 단조롭고, 길이를 바꾸면 리듬이 생긴다 [71]. 탐지기의 핵심 지표가 문장 길이 변동(burstiness)이다 [70].

### 4-5. 구체성: 형용사 대신 명사와 숫자
- 홍보체를 객관 문장으로 바꾸면 사용성 27%, 간결 58%, 스캔 47%, 결합 124% 상승 [72].
- 직원이 "그것" 대신 "그 티셔츠"라고 말하면 만족 8.9%, 지출 30% 상승 [74].
- 리뷰에서 뽑은 문장 그대로 만든 헤드라인이 대조군보다 클릭 400% 상승 [75].
- 소개 문단에는 브랜드 고유 사실(창업 연도, 장소, 사람, 재료, 실패담) 1개 이상 [89].
- 폼·인증 카피에는 소요 시간과 필요 이유 한 줄. 숫자는 사용자의 다음 행동 기준으로(남은 인원 vs 끝난 인원) [83].

### 4-6. 제약: 축별 하나
- radius 스케일 1개, 그림자 1광원 1틴트, 간격 사다리, 아이콘 1패밀리 1굵기 [14].
- 60-30-10은 팔레트가 아니라 비율. 포인트색의 힘은 희소성에서 나온다 [36]. 색은 hex 나열이 아니라 역할의 작은 집합이며 순서는 중립색→CTA 1색→상태색→대비표 [37].
- 서체 2개(디스플레이+본문), 굵기 4종 이내 [32].
- 손맛 장치(그레인 오버레이, 손글씨 주석, 어긋난 겹침)는 페이지당 1종, 이유 문서화, Editorial/Kinetic 한정 [59][60].
- 팔레트 확정 전 흑백 스크린샷으로 위계 확인(색 없이도 CTA가 보여야 함) [40].

## 5. 프로세스

### 5-1. 원샷 대신 3단계 + 반복 루프
1. **입력 게이트**: paper/ink/cta hex 3개, 서체 2개(이유 포함), 레퍼런스 2개(A의 X + B의 Y)와 안티 레퍼런스 1개, 히어로 문법, 목표/레이아웃/콘텐츠/제약 4칸. 하나라도 비면 생성 시작 금지 [42][23][115].
2. **토큰 플랜(1패스)**: 팔레트 hex 4~6, 서체 역할 2+, ASCII 와이어프레임, 시그니처 요소 1개 [6].
3. **자기비판(2패스)**: "어떤 비슷한 페이지에도 낼 법한 기본값"을 지목하고 무엇을 왜 바꿨는지 적은 뒤에 코드 [6].
4. **코드**: tokens.css 변수만 사용 [117]. 원샷 다화면이 아니라 히어로 → 핵심 섹션 → 나머지 순으로 섹션 단위 생성·검수 [140]. 섹션 3개마다 규칙 준수 재점검 [127].
5. **요소 단위 수정**: 전체 재생성 대신 요소 코멘트로 반복. 요소 코멘트가 필요 수정의 약 95%를 덮는다 [23]. 수정은 요소 주석 / 전역 다이얼 / 방향 전환 3층으로 나누고, 위치는 스크린샷 번호나 DOM 셀렉터로 특정하며, 색→깊이→타이포→모션 순의 별도 패스로 돌린다(§5-5) [143][144][147].
6. **감지 0건까지**: 결정론적 검출 규칙(정규식/CSS 파서)을 돌려 0건이 될 때까지 /polish. 머지 조건 [115].
7. **재수렴 집계**: 24개 생성 후 실제로 어떤 서체·색으로 수렴했는지 세고 금지 목록을 라운드마다 갱신 [111].

### 5-2. 디자인 토큰·스타일 가이드 선행
- 카테고리마다 70줄 내외의 DESIGN.md(Brand / Color / Type / Spacing / Components)를 저장소에 두고 빌더·리뷰어가 먼저 읽는다. Stitch/Claude Code/Cursor가 생성 전 로드하는 지속 컨텍스트 포맷 [116].
- 토큰 3계층: primitive(blue.500) → semantic(color.action.primary, --ink) → component(button.primary.background). 한 계층만 참조. 공식 category.concept.property.variant.state [41].
- 값 1개=토큰 1개. 같은 색값에 이름이 여럿이면 모델 출력이 흔들린다 [117].
- 팔레트 절차: 소스 색 1개 → 키 색 확장 → 톤 사다리 → 역할 슬롯(M3 Dynamic Color 절차) [39]. 파생색은 HSB 규칙 [38]. 다크는 라이트 반전 금지, 별도 정의 [40].
- 서체 절차: 브랜드 형용사 3개 → 후보 3종 → 실제 카피로 렌더 비교 → 이유 기록. 한글 본문 16~17px/행간 1.5~1.7 [26][32].
- 이미지 프롬프트 스캐폴드: Gemini 공식 템플릿 3종(실사/제품/일러스트) 중 카테고리당 하나 [102]. 서술형 3~5문장, 하드웨어·렌즈·조명 이름, 긍정 서술 [101]. 끝에 불완전함 블록(visible pores, subtle asymmetry, flyaway hairs, fabric grain; no plastic skin, no CGI) [97][119]. 카테고리별 장비 프리셋(§7) [98]. Midjourney는 `--style raw --s 50`, 브랜드 룩은 `--sref` 하나로 고정 [99]. UGC·현장감 컷은 Flux dev+아마추어 스냅샷 LoRA(가중치 0.3~0.5, guidance 2.5~4)로 만들고 광고 톤 컷과 섞는다 [100].

### 5-3. 리뷰 루프
- 리뷰 점수 비중: 타이포 위계·여백·리듬(디자인)과 읽기 쉬움(사용성)에 70%, 모션 20% 이하 [47].
- 판정은 겹침 개수로: Krebs 상위 5개 중 2개 이상, 또는 A급 1개+B급 2개 [1][63].
- 리뷰 첫 항목: 서체 선택 이유+크기 대비(디스플레이/본문 4:1 또는 명시 규칙), 레이아웃이 Grid/Unusual 중 어느 계열인지 선언 [62].
- 이미지 QA: 미드저니 룩 6요소 중 3개 이상, 배경 텍스트, 반복 패턴, 광원 방향 [93][95][96].
- 카피 QA: 어휘+구조 2개 이상 겹칠 때 판정. 금지어는 주의 신호 [63][65]. 한국어는 어휘보다 구조 신호(§3-5)를 먼저 본다 [124].
- 렌더 QA: 코드 grep만이 아니라 1440·1024·390px 스크린샷을 보고 판정하고, 위반은 `파일:줄` 형식으로 기록한다 [145][146][159]. 동일 패턴의 실제 서비스 화면 3개와 나란히 비교한다 [142].

### 5-4. Claude Code용 규칙 파일 예시

`.claude/rules/design-anti-ai.md` (또는 CLAUDE.md에 포함). 원칙 위주로 쓰고 세부 px는 DESIGN.md에 둔다 [112].

```markdown
# Forblune 디자인 규칙 (빌더 필독)

## 시작 전
- `_reference/design-language.md`와 이 사이트의 `DESIGN.md`를 먼저 읽는다.
- 브리프에 paper/ink/cta hex, 서체 2개+이유, 레퍼런스 2개(A의 X + B의 Y), 안티 레퍼런스 1개,
  히어로 문법이 없으면 코드를 쓰지 말고 누락 항목을 물어본다.

## 코드 전 2패스
1. 토큰 플랜: 팔레트 hex 4~6개(역할명), 서체 역할 2개, ASCII 와이어프레임, 이 페이지가 기억될 요소 1개.
2. 자기비판: 위 플랜에서 "비슷한 어떤 페이지에도 낼 법한 기본값"을 지목하고, 무엇을 왜 바꿨는지 3줄로 적는다.
   대담함은 시그니처 1곳에만 쓴다.

## 금지 기본값(이유가 브리프에 없으면)
- 색: hue 240~285 채도 60%+ 주색, 크림 #F4F1EA/#faf9f5/#f5f1ea~#e8dfcb ±3% + 세리프 + 테라코타/세이지/브라스,
  틸 #16d5e6류, 컬러 box-shadow, 카드 한쪽 컬러 보더, 그라데이션 배경(시작/끝 hex+각도+종류 주석 없이).
- 서체: Inter/Geist/Space Grotesk/Playfair/Instrument Serif/Fraunces/Spectral. 산세리프 헤드라인 안 이탤릭 세리프 단어.
```

### 5-5. 생성 단위·수정 방식·리뷰 자동화 (process 후반 보강)

**생성 단위: 원샷 다화면 금지, 섹션 순서대로**
- DIS 2025 GenUI Study(UX 실무자 대상): 여러 화면을 한 번에 생성하면 "너무 복잡하고 압도적이며 프롬프트와 어긋난 불필요 기능"이 자주 섞이고, 약 1/3은 화면 하나씩 채팅으로 만들며 생성물을 자기 사고의 중간 단계로 취급했다. 개별 UI 요소를 편집할 수 없는 것이 빠르고 저렴한 반복을 막는 핵심 한계로 지목됐다(원문은 403, 초록·요약 기준) [140]. 사이트는 히어로 → 핵심 섹션 → 나머지 순으로 섹션 단위 생성·검수하고 각 단계에서 요소 단위 수정을 지시한다.
- 국내 디자이너 관찰: 클로드 디자인은 "특별히 지시하지 않으면 특유의 스타일로 수렴"하고 "작업이 길어질수록 처음 설정한 디자인 규칙에서 벗어난다" [127]. 긴 빌드 세션은 섹션 3개마다 팔레트·서체·radius 준수 여부를 재점검하고, DESIGN.md를 매 섹션 시작 시 다시 읽힌다.
- 히어로는 2~3안을 나란히 만들어 비교한 뒤 채택한다. 국내 실무자는 히어로만 7번 이상 수정했고, 지목된 AI 티는 유리 같은 반투명 카드·그라데이션 글자·과한 시각 효과·"어디서 많이 본 그 느낌"이었다. 목업에는 "진짜 작동하는 것처럼" 실제 데이터(숫자·차트·상태 표시)를 넣으라고 지시했다 [125]. 리뷰 코멘트는 "왜 별로인지"(원인)를 적는다.
- A/B 시안을 만들 때는 색·레이아웃·서체 중 변수 하나만 바꿔 비교하고 무엇이 달라졌는지 기록한다. 대규모 수정은 주석 기능으로 처리한다 [148].

**레퍼런스는 느낌이 아니라 스펙으로**
- SpecifyUI(디자이너 16명, Google Stitch 대조): 시각 레퍼런스를 영역 분할·VLM으로 구조화 스펙(전역 레이아웃·색 체계·형태 언어 + Page→Section→Component)으로 추출해 재조합하는 방식이 프롬프트 반복보다 스타일 일관성 5.52 vs 4.18, 컴포넌트 정확도 5.69 vs 4.20, 편집 제어감 5.88 vs 3.94, 의도 반영 6.06 vs 4.25(모두 통계적 유의), 타이핑 73% 감소. 초기 설정은 +130초지만 수정은 작업당 -150초 [139]. 브리프에는 레퍼런스를 "전역: 레이아웃 그리드·색 체계·형태 언어 / 페이지: 섹션→컴포넌트 목록"으로 분해해 넣고, 수정도 스펙 항목 단위로 지시한다.
- Lazyweb MCP는 실제 앱 화면 25.7만 장을 에이전트가 검색·유사도 조회하는 도구로, 철학은 "감이 아니라 근거로 디자인(design with evidence, not vibes)"이다. `/lazyweb-design-improve`는 현재 화면을 스크린샷 → 유사한 상위 앱 화면 검색 → 개선안 제시 순서다 [142]. 리뷰 단계에 "현재 화면 스크린샷 → 동일 패턴의 실제 서비스 화면 3개와 나란히 비교" 절차를 넣고 차이를 수정 지시로 바꾼다.

**DESIGN.md에는 Don't와 상태가 있어야 한다**
- "Apple 느낌으로 만들어줘"가 실패하는 이유는 색·타이포·간격·그림자·컴포넌트 상태·반응형 규칙이 전달되지 않기 때문이다. DESIGN.md에는 색상명+용도, hover/focus/active/disabled 상태, container width·grid·spacing·breakpoint, 그리고 Do's and Don'ts를 적어야 한다. AI는 "해야 할 것"만 주면 과하게 적용하는 경향이 있어 금지 규칙이 필수다. "디자인 시스템은 색상표가 아니라 배치 규칙이다" [128]. 카테고리 DNA 문서에 색 이름+역할, 컴포넌트 5상태, container/grid/section spacing 수치, Don't 목록을 빠짐없이 넣고 Do만 있는 문서는 승인하지 않는다.
- Lovable/Bolt/v0/Replit에 기존 디자인 시스템을 넣은 비교: Knowledge/Context 필드에 브랜드 가이드·tailwind.config 변수·Google Fonts 링크를 넣는 것이 효과적이고, 컴포넌트는 NPM 패키지 > GitHub 동기화 > 코드 붙여넣기 순. 모든 도구가 shadcn/Tailwind 기본이라 "기본값에서 멀어질수록 수동 지시가 늘어난다" [138]. shadcn 기본값에서 먼 Editorial·Kinetic은 서체 링크·토큰 파일·컴포넌트 예시 코드를 프롬프트에 직접 동봉하고 이 추가 비용을 일정에 반영한다.

**수정은 3층으로 나누고, 위치를 특정하고, 패스를 분리한다**
- Claude Design의 반복 수정은 3층이다: 인라인 코멘트(여러 요소에 주석 후 일괄 반영), Tweaks 패널(타이포 스케일·간격·팔레트를 재생성 없이 조정), 채팅(팔레트·레이아웃·대안 방향 등 광역 변경) [143]. 우리 수정 지시도 요소 주석(간격·컴포넌트 교체·색) / 전역 다이얼(타입 스케일·간격 배수) / 방향 전환(채팅)으로 분리하고, 사소한 수정으로 전체를 재생성하지 않는다. 반복 비용도 이유다. Claude Design 반복은 "30분에 주간 한도 소진"이라는 불만이 있어 요소 단위 수정이 비용 면에서도 유리하다.
- 텍스트만으로 지시하면 "전역 적용" 오류와 의도-이해 간극이 생긴다. 스크린샷·그린 주석·DOM 선택으로 피드백을 디자인의 특정 부분에 접지시키는 생성→검토→주석→수정 루프가 그 간극을 줄인다 [144]. 리뷰어는 텍스트 지적 대신 스크린샷에 번호를 찍거나 DOM 셀렉터로 위치를 특정해 넘긴다.
- 수정 라운드는 한 번에 몰지 말고 색 → 깊이/그림자 → 타이포 → 모션 순의 별도 패스로 나눈다. NextJS+Mantine 실사용에서 모든 요소에 동일한 그림자가 "결정적 AI 티(dead giveaway)"였고, 타이포 미세조정(히어로 -0.01em, 라벨 0.08em) 단계는 "차이가 미묘하다"고 저자가 인정했다 [147]. 그림자·radius가 전 요소 동일한지는 별도 검사 항목으로 둔다.

**리뷰 자동화 형식**
- Vercel web-design-guidelines 스킬은 17개 카테고리 100개 규칙을 매번 GitHub 최신 command.md에서 가져와 `파일:줄` 형식으로 위반을 보고한다. 항목 예: 포커스 링, 히트 타깃 24px 이상(모바일 44px), prefers-reduced-motion, `transition: all` 금지, APCA 대비 [145]. 우리 규칙 파일도 "버전관리되는 규칙 파일 1개 + 파일:줄 출력" 형식으로 두고 리뷰어 에이전트가 매 회 최신본을 읽게 한다.
- OneRedOak design-review 워크플로는 Playwright MCP로 실제 렌더된 UI를 열어 상호작용·반응형·시각 완성도·접근성·견고성·코드 건강을 다단계로 검토하고, `/design-review`로 git diff 기준 자동 리뷰한다. 디자인 원칙과 브랜드 가이드는 CLAUDE.md에 상주한다 [146]. 코드 grep 검사에 더해 브라우저 렌더 스크린샷(1440·1024·390px, §3-8) 기반 리뷰 단계를 넣고 리뷰어 프롬프트에 스타일 원칙을 항상 포함시킨다.

### 6-1. 국내 논의의 진단과 코딩애플 영상 요지

- **진단은 같다.** 국내 논의도 "분포 수렴"으로 설명한다. 브런치 fromhyuns(2026-02)는 바이브코딩 결과물이 닮는 형태를 "Inter 폰트, 보라색 계열 그라데이션, 다크 모드 위에 정갈하게 정렬된 컴포넌트"로 특정하고, 원인을 취향이 아니라 모델의 분포 수렴으로, 보라를 "가장 실패하지 않는 선택"으로 본다. "개방된 도구가 오히려 획일화를 초래"하는 역설이며, 해법은 초안을 이해한 뒤 의도적으로 어긋나는 선택을 하는 것 [20][21]. 예시 사이트마다 "기본값에서 의도적으로 벗어난 결정" 3개(색·서체·레이아웃 각 1개)를 명시하는 §4-3 규칙의 출처다.
- **코딩애플 「AI 냄새가 싫다는 사람들」(2026-08, 조회 27만) 요지**(1차 기준서 §0·§1에 스크린샷 분석으로 정리돼 있다): 상품 설명·뉴스·코드 리뷰·웹사이트에서 AI 출력을 그대로 복사한 콘텐츠가 양산되며 사용자가 피로감을 느끼고, "AI 냄새"가 나면 신뢰가 떨어진다. 웹 디자인에서 지목된 주범은 획일화된 폰트, 누런(크림색) 배경, 의미 없는 UI 요소, 이모지 남발, 클릭되지 않는 버튼처럼 생긴 요소, shadcn류 기본 컴포넌트를 그대로 쓴 무난함이다. 화면 근거로 든 사례는 spanlens.io의 크림 배경+Inter/Geist+모노 대문자 소제목("전부 다 클로드의 기본"), agentsroom.dev의 깜빡이는 점 pill 배지와 아이콘 3장 카드, engineprompt.net의 이모지 아이콘과 세리프 제목+"supercharge" 카피다. 판정의 핵심은 "크림 배경 자체가 아니라 이유 없이 기본값을 그대로 쓴 것이 문제"이며, 해법은 자동 생성에 맡기지 않고 직접 개입(색 조합 직접 선택, 레퍼런스 확보), 원샷이 아닌 반복 수정, AI 이미지는 조명·질감·구도를 지정하고 타이포는 따로, AI 문체 대신 자기 말투, 그리고 "명령을 내리는 사람의 도메인 지식이 병목"이라는 것이다(1차 기준서). 이번 korea-context 수집에서는 YouTube 접근 차단과 검색 인덱스 미반영으로 영상 원문을 독립 확인하지 못했다. 검색에 잡힌 유사 제목 「AI 냄새 안 나게 디자인 하는 방법」(2026-02-28)은 oembed 확인 결과 채널이 코딩애플이 아니어서 제외했다. 위 요지는 1차 기준서의 스크린샷 분석을 그대로 신뢰한 것이며, 이 문서의 §3 표에서 같은 항목이 해외 정량 자료(Krebs, Anthropic 스킬)로 교차 확인된다 [1][6].
- **국내 뉴스의 슬롭 정의.** 국내 매체는 AI 슬롭을 "생성형 AI로 대량 복제·양산된 저품질 콘텐츠"로 정의하고, 한국이 AI 슬롭 채널 누적 조회수 84억 5천만 회로 세계 1위 소비국이라고 보도했다. 유튜브는 슬롭을 "반복적이고 획일적인 콘텐츠"와 "이용자의 감정을 과도하게 자극하는 콘텐츠" 두 갈래로 규정하고 수익을 제한한다 [135]. 이 두 정의가 §3-5의 "구조 반복 3회+ / 자극 카피" 리뷰 항목이 됐다.
- **국내 실무자의 경험.** 렛서(2025-09) 비교: Lovable 결과는 "AI로 만든 티가 너무 많이 남", Webflow AI는 "템플릿 텍스트 수정 수준". 티를 줄인 워크플로는 기획(콘텐츠 초안) → Figma 목업 → Cursor 구현 → 스크린샷·레퍼런스 이미지를 보여주며 반복 수정이었다 [22]. GPTers 사례(Claude Code 랜딩)에서 지목된 AI 티는 유리 같은 반투명 카드, 그라데이션 글자, 과도한 시각 효과, "어디서 많이 본 그 느낌"이었고, 디렉션은 "효과 빼고 더 절제해줘", "가짜 그림 말고 진짜 작동하는 것처럼", "실제 데이터가 든 것처럼 디테일을 넣어줘"였다 [125]. 브런치 Jonghyuk Lim(2026-07)은 클로드 디자인의 한계로 스타일 수렴·규칙 이탈·컨텍스트 제약을 들고, 방향성 5개 도출 → 피그마에서 시스템 정리 → 코드 배포 조합을 권했다 [127]. 세 사례 모두 결론이 같다. 원샷 생성물은 초안이고, 레퍼런스 스크린샷을 첨부해 "이 지점처럼" 요소 단위로 고친다.

### 6-2. 국내 사이트에서 특히 티 나는 요소

해외 텔(§3)에 더해 한국어 사이트에서만 또는 먼저 드러나는 것들이다.

- **한글 폴백 미지정과 라틴 자간의 한글 적용.** AI 단일 HTML은 `font-family`에 영문 스택만 지정해 한글이 맑은 고딕/시스템 폴백으로 렌더되고, 라틴 헤드라인 자간(-0.04em)이나 대문자 자간 넓힘을 한글에 그대로 적용해 "번역된 사이트" 느낌을 낸다. 서체명보다 먼저 드러나는 티다 [151][152]. 수치는 §6-4.
- **영어 장식 문구와 직역 라벨.** 히어로의 "EXPERIENCE THE FUTURE"류 대문자 영문, "Get a Certificate"(KB 앱 예)처럼 한글을 그대로 옮긴 라벨. 한국 기업 영어 카피는 "한글 버전과 최대한 비슷하게" 번역하는 데 갇혀 있고, 최종 컨펌자가 한국 임원이라 영어 사용자의 UX는 배제된다 [131]. 영어 사용자가 읽어도 의미가 서는지 검증하지 못하면 넣지 않는다.
- **한국어 AI 문투.** 커뮤니티 기준은 쉼표 남발과 접속어(이처럼·또한·이를 통해·이를·이러한·마침내) 반복 [88]. 국내 관찰(교실밖, 2026-05)은 구조를 지목한다: "A이기도 하고 B이기도 하다" 대칭 구문, 문단마다 그러나·또한·따라서·한편, 3개 이상 개념 나열, 단락 첫 문장 선언 후 반복 설명, "~가 중요하다/성찰이 필요하다" 마무리, 피동으로 주어 소실, 강약 없는 어조, 혁신적·심오한·패러다임. 빈출어는 다양한·중요한·통해·고려·제공·관련·기반·이러한·효과적·특징이다. "번역체만 섞여도 AI가 쓴 글이구나 바로 들키는" 것이 한국어의 특성이라는 마케팅 매체 지적도 있다 [124][156]. 탐지 도구 무하유는 경험·감정·비유 없는 평이한 톤, 무견해, 키워드 반복을 [89], 작가 관찰은 "급변하는 현대 사회에서" 도입과 같은 길이 문장 반복을 든다 [90]. 국내에 유통되는 "ChatGPT가 가장 많이 쓰는 100가지 표현" 류는 영어 목록의 기계 번역이라 기준으로 쓰지 않는다 [157].
- **"보라 하나+회색" 공식.** 국내 바이브코딩 가이드가 "강조색은 앱 전체에서 딱 하나, 보라 하나, 나머지 회색 / 그림자 opacity 4% / 검정은 #2A2A2A"를 프로 UI 공식으로 퍼뜨린다. 절제 원리는 맞지만 보라 고정은 AI 퍼플을 재생산한다 [158][25]. §3-8 참조.
- **푸터가 영어 카피라이트 한 줄.** 한국 사용자는 사업자정보 블록이 없는 사이트를 데모/생성물로 읽는다. §6-3.
- **모션.** 사용자 입력을 무시하고 끝까지 재생되는 애니메이션, 정해진 경로 반복, 과한 반동이 국내 디자이너가 지목한 "AI 모션의 티"다. 애플 WWDC 원칙(중단 가능성, 스프링 물리, 저항감 계산식)을 규칙 파일로 주면 개선된다. "취향은 재능이 아니라, 설명하고 나면 규칙이 된다" [136].
- **그라데이션 지시법과 색 절차**는 국내 커뮤니티·에이전시 자료가 해외와 같은 결론이다. "색상+스타일+방향" 3요소를 함께 줘야 보라 떡칠이 안 나고(GrainyGradient / Subtle Gradient 구분) [30], 주색→보조색→그레이스케일 테스트→60:30:10, 다크는 #000 대신 #121212류에 라이트 반전 금지 [40].

### 6-3. 한국 사용자가 신뢰하는 사이트의 특징

**정보 밀도는 허용이 아니라 신뢰 신호다.**
- 한국 상세페이지가 미국보다 긴 이유: 서구권은 "핵심 블록 몇 개로 구조 종료, 대표 성분·핵심 메시지만 전면, 긴 설명·세부 근거 최소화"인 반면 동아시아권은 제품을 맥락 속 요소로 이해해 관계 중심으로 근거를 확장하며, 아마존은 템플릿 기반 정리, 네이버는 셀러의 표현 자유와 상세 확장을 허용한다 [132]. 한국 커머스/서비스 예시는 해외식 "히어로+3카드+CTA"로 끝내지 말고 스펙표·근거·사용 장면·FAQ·후기 등 정보 밀도가 있는 하단 섹션을 갖춘다. 밀도가 있어야 "실제 영업 중"으로 읽힌다.

**사업자정보 블록은 법이자 신뢰 장치다.**
- 전자상거래법 제10조 제1항: 사이버몰 운영자는 소비자가 사업자 신원을 쉽게 알 수 있도록 (1) 상호 및 대표자 성명 (2) 영업소 주소(불만처리 주소 포함) (3) 전화번호·전자우편주소 (4) 사업자등록번호 (5) 이용약관 (6) 대통령령으로 정하는 사항을 초기화면에 표시해야 한다 [150]. 실무에서는 통신판매업 신고번호·개인정보관리책임자·호스팅 제공자를 더하고 "사업자정보확인" 링크를 다는 것이 관행이며, 빌더(아임웹)는 이를 "하단 필수정보"로 안내하고 마케팅 커뮤니티는 이 정보 박스가 쇼핑몰 신뢰도를 높인다고 본다 [133]. `© 2026 Brand. All rights reserved.` 한 줄 푸터는 즉시 데모로 읽힌다.
- Commerce·Product·Corporate 예시의 푸터에는 4열 링크 대신 국내 표준 블록을 한국식 한 줄/두 줄 밀도로 넣는다. 가상 값이라도 형식은 정확하게: `상호 ○○ | 대표 ○○○ | 사업자등록번호 000-00-00000 | 통신판매업신고 제2026-서울마포-0000호 | 주소 | 고객센터 02-000-0000 | 개인정보책임자 ○○○ | 호스팅 제공자 ○○ | 이용약관 · 개인정보처리방침 · [사업자정보확인]`.

**후기는 인증 표기가 있어야 후기다.**
- 한국 소비자의 97.2%가 구매 전 후기를 확인하지만 신뢰한다는 비율은 70.2%에 그친다. 플랫폼은 네이버 "AI 영수증 인증 리뷰", 요기요 "구매·결제 완료자만 작성", 동영상·사진 리뷰, 올리브영 "탑리뷰어" 공개 같은 인증 장치를 도입했고, 2025년 말에도 "리뷰 1건당 7000원" 조작 대행이 성행한다는 보도가 있다 [134]. 별점+이니셜 아바타 카드는 해외 텔(§3)이기도 하지만 한국에서는 인증 부재 자체가 불신 신호다.
- 후기 컴포넌트에는 영수증/구매 인증 표시, 작성일, 구매 옵션, 사진 썸네일, 도움돼요 수를 넣고, 인증 표기가 없는 후기 카드는 아예 넣지 않는다. 헤드라인은 네이버 플레이스·쿠팡·앱스토어 리뷰에서 뽑은 표현 5개로 만든다 [75].

**뷰포트.** 한국은 Statcounter 2026-07 기준 데스크톱 61.15% / 모바일 37.92%로 데스크톱 우세이고 스마트폰 보유율은 98.8%다. 어느 한쪽만 정돈된 페이지는 실패다(§3-8) [159][160].

### 6-4. 한글 타이포 수치

- **공공 기준(KRDS)**: 기본 서체 Pretendard GOV, 본문 17px(최소 16px), 행간 150% 이상, 본문 자간 0px, 굵기 최대 4단계(Regular 400/Bold 700), Display/Heading/Body 3계층+Navigation/Label 토큰, 대비 4.5:1(AA). 한글은 알파벳보다 베이스라인이 낮아 행간을 더 넓게 잡아야 빽빽해 보이지 않는다 [32].
- **국내 주요 사이트 실측**(네이버·다음 뉴스, 퍼블리, 리디 등): 본문 17px 내외, 색 #333 근처, 자간 음수(-0.34px~-1px), 행간 1.6~1.9(퍼블리 1.8), keep-all은 퍼블리·인디포스트·리디북스만 적용, 폴백은 Apple SD Gothic Neo → 맑은 고딕 순 [151]. Pretendard 공식 폴백 스택: `"Pretendard Variable", Pretendard, -apple-system, …, "Apple SD Gothic Neo", "Noto Sans KR", "Malgun Gothic", sans-serif` [152].
- **적용 규칙**: 본문 16~17px, 행간 1.6~1.8, 자간 -0.01~-0.02em(영문 헤드라인용 -0.02em 이하를 한글 본문에 일괄 적용 금지, 한글에 양수 자간 금지), 제목·짧은 문장 `word-break: keep-all`, 굵기 4단계 이내, body에 한글 폴백 스택 명시, 웹폰트는 파일당 CSS 링크 1개+`font-display: swap`. lint 규칙으로 둔다.
- **Pretendard 판정 변경.** Pretendard가 국내 웹·앱의 사실상 표준이 된 이유는 무료 오픈소스, Apple 시스템 서체 특유의 미려함 재현, 한글·영문 조화, 가변폰트 지원이며 다수 서비스가 본고딕에서 갈아탔다 [31]. 초판의 "24개 중 Pretendard 단독 4개 이하" 쿼터는 철회하고, 판정을 "제목 서체(또는 굵기·크기 대비 규칙)를 결정했는가 / 한글 폴백을 지정했는가 / Inter를 함께 로드하지 않았는가" 3항으로 바꾼다(§3-3). Pretendard는 UI/본문 기본값으로 안전하지만 그 자체가 "국내 서비스 평균 얼굴"이므로 디스플레이 서체는 카테고리별로 따로 고른다.
- **한영 섞어짜기**: 같은 pt에서 영문이 물리적으로 작아 보이므로 영문 +3~5%, 베이스라인 의도적 결정, 숫자는 라이닝(모던) 스타일. 가장 조화로운 것은 섞지 않는 것 [33].
- **국내 서체 지형**: 본문·UI=Pretendard·SUIT(숫자/라틴 정돈, 가변)·Wanted Sans / 제목·배너=G마켓 산스(이커머스 배너 연상 강함)·에스코어 드림 / 개성=배민 시리즈·Gowun Dodum/Batang. 저작권 분쟁은 "어디서 받았고 어떻게 쓰는지"에서 생긴다 [35]. Paperlogy는 한글 2,780자만 수록한 디스플레이 서체라 본문 폴백 필수 [34].
- **2026 서체 업계 방향**: 산돌은 "사람의 흔적", 투박하고 손맛이 느껴지는 표현, 글자가 형태·질감·공간의 주인공이 되는 타입 중심 디자인을 꼽는다 [130]. Editorial/Kinetic에 타이포가 주인공인 섹션 최소 1개.

### 6-5. 한국어 카피: UX 라이팅 가이드와 톤

- **국내 UX 라이팅 공개 가이드**: 토스 8원칙(잡초 제거, 빈 문장 제거, 핵심 메시지 집중, 보편적 언어, 강요보다 제안, Easy to speak, 청유형, 밈 금지) [78][79]; 토스 실례("받는 분"→"어디로 돈을 보낼까요?", "이체가 완료되었습니다"→"~로 ~원을 보냈어요") [80]; 대출 상환 알림을 수고 인정 문장으로 바꿔 반응 상승 [81]; SKT 『사람 잡는 글쓰기』("NEW 단말"→"개통한 적이 없는 휴대폰", "언택트"→"비대면") [85][86]; 신한카드 6보이스·7톤, CTA A/B에서 전환율 차이 [87]; 배민(본인인증에 "2분 만에 끝내기"+법적 이유) [83]; 네이버파이낸셜 대체어 사전(스니펫 확인) [92]; 지형 정리 [84]. 카피 리뷰 마지막 단계에 잡초어 삭제 패스(정말·매우·다양한·최고의·완벽한)와 빈 문장 삭제 패스를 넣고, CTA는 "지금 바로"가 아닌 제안형으로 쓴다.
- **토스체 일괄 적용 금지.** 토스식 친근 대화체를 무작정 따라 하면 "대화인 척"하는 문구가 된다. 삼성처럼 불필요한 감정 표현을 줄이고 신뢰감을 높이는 사실 중심 문구가 맞는 브랜드도 있다. 토스가 통하는 이유는 페르소나·UI·기능의 일관성이다 [82]. NN/g 데이터도 신뢰성이 브랜드 선호의 52%를 설명하고 친근함은 8%만 더한다 [73]. 사이트별로 말투(해요체/합니다체/문어체)와 감정 표현 허용 수준을 카피 규칙 첫 줄에 고정하고, Corporate/Utility/의료/법률/B2B는 감탄·이모지·친근 대화체 없이 사실 문장만, Kinetic/Editorial만 개성 있는 말투.
- **국내 브랜드 카피 참고**: 오늘의집 "누구나 예쁜 집에 살 수 있어"(허들 제거·일상어), 29CM "일상을 채우는 물건"(담백) [91].
- **한국어 이미지 프롬프트**: 요소 과적재가 어색함을 만든다. 렌즈 용도표(인물 85/135, 공간 24/35, 제품 100 macro) [110][123].

### 6-6. 국내 실무자의 프로세스 관행

- **형용사 지시 금지, 스타일 고유명으로.** "세련되게 만들어줘"는 결과를 비슷하게 만든다. 글래스모피즘·브루탈리즘·벤토 그리드·Y2K처럼 UI 스타일의 이름을 정확히 지정한다 [126].
- **DESIGN.md에는 Don't와 상태.** "Apple 느낌으로"가 실패하는 이유는 색·타이포·간격·그림자·컴포넌트 상태·반응형 규칙이 전달되지 않기 때문이고, AI는 Do만 주면 과하게 적용하므로 금지 규칙이 필수다. "디자인 시스템은 색상표가 아니라 배치 규칙이다" [128].
- **브랜드 자산 먼저.** 기업의 기존 디자인 자산을 추출해 모든 생성물에 일관 적용하면 이질감이 완화되고, 디자이너 역할은 요구사항 프레임화와 안목에 의한 정제로 이동한다 [129]. 토스 디자이너도 AI가 더 나은 결과를 내도록 "원칙과 시스템을 설계하는" 역할을 미래로 본다 [137].
- **긴 세션의 규칙 이탈.** 클로드 디자인은 작업이 길어질수록 처음 규칙에서 벗어난다. 섹션 3개마다 재점검, DESIGN.md 매 섹션 재읽기 [127].
- **한국어 튜토리얼(Stitch→Claude Code→Netlify)의 반복 원칙**: 변형 비교는 색상/레이아웃/폰트 한 요소씩만, 대규모 수정은 주석 기능으로, 참고 이미지를 프롬프트와 함께 [148].
- **레퍼런스 우선.** 국내 실무 세 사례(렛서·GPTers·Jonghyuk Lim) 모두 스크린샷 레퍼런스와 요소 단위 수정으로 티를 줄였다(§6-1) [22][125][127].

## 7. Forblune 8개 카테고리별 AI 티 주의 포인트와 대체 지시

각 카테고리 정의는 `design-language.md` §2~§9를 따른다. 아래는 그 정의를 지킬 때 특히 밟기 쉬운 지뢰와 대체 지시다.

### 7-1. Editorial (취향·이미지 · Desire · Slow · 아이보리+차콜+저채도 포인트)
주의 포인트
- 정의 자체가 2세대 텔과 겹친다: 아이보리 배경+세리프+베이지/브라운 포인트 = "크림+고대비 세리프+테라코타" 클러스터 [6][7][8]. Claude 팔레트(#faf9f5/#cc785c) 복제 위험 [28].
- 산세리프 헤드라인 안 이탤릭 세리프 단어 1개, 초대형 이탤릭 세리프 히어로 [4][3].
- 사진 위 pill 라벨, 장식 사진 크레딧, "01 / 4" 이미지 페이지네이션, Scroll 큐 [8].
- 화보 이미지가 장식이면 사용자가 무시한다 [105]. 균등 상품 그리드만 반복하면 매거진 리듬이 없다.
- 헤어라인 룰+radius 0+빽빽한 신문 다단의 "브로드시트" 3종 세트는 Anthropic 스킬이 지목한 AI 기본 룩 3번이다. 크림+세리프(1번)를 피하려다 이쪽으로 미끄러지기 쉽다 [6].
- 카피의 "감각 동사"가 "스며드는 경험" 류 추상으로 흐르기 쉽다.

대체 지시
- 배경 hex는 §3-2 금지 목록 ±3% 밖에서 종이·사진에서 뽑고, 잉크색·포인트를 세트로 정의. 이유를 DESIGN.md에 한 줄("촬영 배경지 #… 에서 추출") [28][39].
- 서체: Gowun Batang/나눔명조 디스플레이 + SUIT 본문처럼 한글 세리프 시스템 전체로. 이탤릭 세리프 단어 장식 금지 [35][8].
- 그리드: named grid(full/content/breakout) + skinny column. 히어로·특집에서 이미지 2~3장 불균등 스팬, 겹침 1곳 [49][50][51]. 헤어라인 룰·radius 0·다단 중 둘까지만, 나머지는 사진 폭 변주·여백·굵은 룰 1개로 [6].
- 이미지: medium format + Portra 400 + window light 프리셋, 불완전함 블록. 얼굴은 실사 또는 미노출 [98][97][106].
- 손맛 장치 1종 허용(그레인 오버레이 또는 손글씨 주석 1곳), 이유 기록 [59].
- 카피: 리뷰 마이닝 표현 5개, 구체 명사("리넨 셔츠, 6월의 세탁"), 종결어미는 브랜드가 정한 해요체/문어체 하나 [75][74][82].

### 7-2. Kinetic (에너지 · Excitement · Fast · 블랙/네이비+선명한 포인트)
주의 포인트
- 다크+네온 글로우+그리드 라인 배경 = "AI 스타트업" 전형이자 Anthropic 클러스터 2번(근흑+애시드 그린/버밀리언 단일 액센트) [4][6][29].
- 포인트가 hue 240~285 보라·시안으로 흐르면 인디고 텔 [25][7].
- 마퀴 반복, hover scale, 카운트업 남발, opacity:0 리빌 [4][7].
- 대형 영문 슬로건("MOVE BEYOND LIMITS")이 "Build faster. Ship smarter."류 무게 없는 슬로건으로 읽힐 수 있음 [18].
- 갤러리형 획일화(초대형 타이포+스크롤 효과+느린 로드) [56].

대체 지시
- 색에 역할 부여(서비스·카테고리·버튼). 글로우는 핵심 CTA/숫자 1곳만 약하게. 다크는 노이즈 텍스처 1종+채도 높은 단색 1개로 깊이 [29]. 형광 그린/버밀리언 단일 액센트를 기본값처럼 쓰지 않고, 액센트 색의 근거(브랜드·사진에서 추출)를 주석에 남긴다 [6].
- 모션은 중단 가능(hover/scroll 중 즉시 반응), 반복 루프 금지 [136].
- 마퀴 최대 1개, 이징 ease-out quart/quint, 콘텐츠 기본 표시, prefers-reduced-motion [8][4].
- 정적 구간을 반드시 넣어 대비(설계 문서 원칙). 텍스트는 JS 없이 즉시 표시 [56].
- 서체: Paperlogy/G마켓산스 디스플레이+Pretendard 본문, Paperlogy 본문 폴백 필수 [34][35]. 흑백 Kinetic도 가능.
- 브랜드 은유 1개(속도/추적/비행)에서 전환·hover·섹션 형태를 파생 [61].
- 슬로건은 능력을 특정하는 동사구, 강한 인상 뒤 신뢰·진행 방식 정보.

### 7-3. Cinematic (서사·전문성 · Trust · Slow · 블랙/웜 블랙+앰버 1색)
주의 포인트
- 웜 블랙+앰버/브론즈는 클로드 다크 팔레트(#181715+#cc785c)와 가깝다 [28].
- 자간 넓힌 대문자 섹션 라벨은 정의상 허용이지만 "클로드 미학"의 구성 요소이기도 하다 [27].
- 원칙 3~5개에 번호를 붙이는 순간 장식 번호 아이브로우로 읽힐 수 있다 [8][6].
- 다크+중간 회색 본문 저대비 [1][3]. 필름 그레인 전면 일괄 [108].
- 인물 사진을 AI로 만들면 신뢰의 핵심(사람)이 무너진다 [106]. 미드저니 룩의 균일 조명은 다큐멘터리 톤과 정반대 [93].

대체 지시
- 앰버 hex는 #cc785c 근처를 피하고, 다크는 #0a0a0a~#121212에 웜/쿨 기운을 정해 라이트 반전 없이 별도 정의 [28][40].
- 본문 대비 4.5:1 이상, 본문 폭 55~75자, 회색 본문 금지 [3][32].
- 번호는 Brief→Route→Safety→Flight→Review처럼 실제 공정일 때만. 라벨은 정보 문장 [6][57].
- 이미지: Arri Alexa + anamorphic + chiaroscuro 프리셋, "한 방향 주광+반대편 그늘" 명시. 인물은 실사 촬영 또는 미노출 [98][96][106]. 그레인은 배경면 1~2곳.
- 카피: Belief→Process→Proof에 구체(장비명, 확인 항목, 연도). 합니다체. 소개 문단에 고유 사실 1개 이상 [89][74].

### 7-4. Corporate (신뢰·정보 · Trust/Clarity · Balanced · 화이트+네이비/딥 그린)
주의 포인트
- 검정 텍스트/흰 배경/파란 CTA "사무실 색" [15]. 카드 규격 통일 원칙이 곧 균일성 텔로 미끄러진다 [11][5].
- 통계 행(수치·인증)이 "10K+/99.9%" 형식으로 흐르기 쉽다 [4][8].
- 3열 아이콘 카드, 이니셜 아바타 후기, 로고 수프, FAQ 아코디언(SEO 명분 2026-05 소멸) [23][58].
- 헤드셋 상담원·악수 스톡 [109]. 실적 형용사("국내 최고") [72].

대체 지시
- 스위스 원칙: 모든 텍스트 좌정렬·ragged-right, 히어로도 좌측 컬럼에서 시작 [52].
- 중립색을 브랜드 hue로 물들인 회색, CTA는 네이비/딥 그린 1색 [39].
- H2를 정보 문장으로. 수치는 기준일·단위 명시, 없으면 삭제 [57].
- FAQ는 실제 문의 3~5개, 펼친 dl. 로고 월은 로고만 [58][8].
- 실제 직원 사진(사용자가 소개글보다 오래 본다) 또는 미노출 [105].
- 서체: Pretendard/Noto Sans KR+본명조, 본문 17px, 행간 1.6, 굵기 4종 [35][32].
- 카피: PAS 1세트, 형용사→수치, 톤 4축에서 enthusiastic 중간 이하, 느낌표 0, 합니다체. 약어는 우리말 풀이 먼저 [77][72][73][85].
- 푸터: 국내 표준 사업자정보 블록(상호·대표·사업자등록번호·주소·전화·이메일·이용약관·개인정보처리방침), 영어 카피라이트 한 줄 금지 [150][133]. 하단에 스펙·근거·FAQ 등 정보 밀도 있는 섹션 [132].

### 7-5. Product (기능·사용성 · Clarity · Balanced · 화이트+브랜드 1색)
주의 포인트
- 히어로 과적재(가치 제안+서브+CTA 2개+로고 월+별점 스트립) [8].
- "CSS로 그린 가짜 앱 화면 OK"라는 우리 정의가 "div 가짜 대시보드"와 충돌한다 [8][4]. 브라우저 크롬 목업, 다크 배경 위 떠 있는 대시보드 [44].
- Linear 스타일 다크+글래스+그라데이션 [29]. 인디고 CTA [25]. Lucide 기본 아이콘 [46][114].
- 프라이싱 토글+FAQ 아코디언+로고 월 3종 세트가 우리 필수 섹션에 그대로 들어 있다 [23].
- "무료로 시작하기/데모 보기"가 Get Started 범용 버튼으로 읽힘 [46]. 통계 히어로 [4].

대체 지시
- 히어로 텍스트 블록 4개 이하, CTA 의도별 1개. 제품 UI가 주인공 [8].

대체 지시

- 숫자는 정직·구체(할인 전후, 남은 수량, 기준 시각), 후기는 실제 리뷰 문장+구매 옵션 [75][8]. 후기 카드에는 영수증/구매 인증 표시·작성일·구매 옵션·사진 썸네일·도움돼요 수. 인증 표기 없는 후기는 넣지 않는다 [134].
