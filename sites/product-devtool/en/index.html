    Automatic retries and fallback retry

    Carrier, SMTP, and APNs error codes are sorted into what to retry and what to fall back on immediately. Idempotency keys are held for 24 hours so the same message never goes twice.

    Idempotency-Key: order-A-20481-shipped · retry: { max: 4, backoff: 'exp' }

    Four steps from one request to a message in someone's hand.

    Scroll sideways to see the whole flow

    Delivery path Webhook callback Event log
    01

    Auth & validation

    Checks API key scope, request schema, and template variables. Anything wrong returns a 4xx immediately, before the message reaches the queue.

    02

    Routing

    Evaluates your channel array and rules — time of day, country, opt-outs — and picks the first channel. 3 ms on average.

    03

    Delivery & retry

    Hands off to the carrier, SMTP, or APNs and classifies the response code, then retries or falls back to the next channel on its own.

    04

    Webhooks & logs

    State changes come back to your app by webhook, and events are kept for 90 days. Search by message ID in the dashboard.
