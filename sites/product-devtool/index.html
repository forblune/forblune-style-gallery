호출 한 번으로 SMS·이메일·푸시가 사용자에게 도착합니다.

채널마다 다른 SDK, 통신사 규격, 실패 처리를 직접 짜지 마세요. Relay API는 하나의 엔드포인트로 세 채널을 보내고, 실패하면 다음 채널로 넘깁니다.

    자동 재시도와 폴백 retry

    통신사·SMTP·APNs 오류 코드를 분류해 재시도할 것과 즉시 폴백할 것을 나눕니다. 같은 메시지가 두 번 가지 않도록 멱등 키를 24시간 보관합니다.

    Idempotency-Key: order-A-20481-shipped · retry: { max: 4, backoff: 'exp' }

    발송 경로 웹훅 회신 이벤트 기록
    01

    인증·검증

    API 키 권한, 요청 스키마, 템플릿 변수를 확인합니다. 문제가 있으면 큐에 넣기 전에 4xx로 즉시 반환합니다.

    02

    라우팅

    채널 배열과 규칙(시간대·국가·수신 거부)을 평가해 첫 채널을 고릅니다. 평균 3 ms.

    03

    전달·재시도

    통신사·SMTP·APNs에 전달하고 응답 코드를 분류합니다. 재시도 또는 다음 채널 폴백을 자동 처리합니다.

    04

    웹훅·로그

    상태 변화를 웹훅으로 앱에 돌려주고, 90일간 이벤트를 보관합니다. 대시보드에서 메시지 ID로 검색됩니다.
